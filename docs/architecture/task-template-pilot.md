# 任务模板配置与运行闭环

## 当前入口调整：TA-R7

旧模板管理组件与从模板创建流程已删除；旧模板创建/非direct任务新建API返回410。任务应用launch和直接创建是唯一新建路径。内部版本/Schema/快照及旧任务读写兼容保留。创建后的任务长期保留，完成或一次性计划执行后仍可编辑、手动再次运行、删除；删除停止计划但保留历史。下文旧模板操作说明仅供历史追溯，当前操作以[用户手册](../guides/user-manual.md#automations)与[TA-R7规格](../sdd/features/task-applications-v1/README.md)为准。

## 2026-10-20：任务应用与运行观察修正

任务中心默认提供「任务应用」入口，复用模板的可选 application 标记、参数项目、不可变发布版本、任务快照及报告，不新增执行运行时。AI 编辑项目附带任务 API 参考；网页仅提交参数，由认证宿主调用 launch 接口，固定发布版本及请求指纹，持久化稳定 taskId，立即执行返回受理状态，定时复用现有服务端调度。旧模板兼容。

智能体 queued 不再误判失败，waiting-approval 继续观察同一 turn 的后续 run，并回写原任务记录。重启时仅恢复已持久化关联运行的观察，不重发任务或 Skill 副作用；无关联中断仍失败，沿用原开始时间的 30 分钟截止。调度扫描锁与任务生命周期分离，等待审批的任务不会挡住其他到期任务。本节覆盖下文旧“审批即失败 / 重启一律失败 / 仅手动”的阶段性描述。

实现、契约与回归追踪见[任务应用规格](../sdd/features/task-applications-v1/README.md)；当前只在登录任务中心使用，不是公开托管的独立网站。

## 使用路径

2026-10-13 阅读口径：任务管理/运行记录是主要入口，模板管理位于任务管理内。模板入参、报告均可选定制；从编辑项目返回自动同步草稿，专用参数预览可用当前身份测试技能及数据接口。任务支持手动/一次/分钟间隔/日/周/月，结构化结果必存；下方较早“模板任务仅手动”等阶段描述已由“周期调度”增量替代。操作步骤见[用户手册](../guides/user-manual.md#automations)。

2026-10-11 可选界面修正（TP-R21）：任务模板的参数收集与报告查看定制均可选，不由执行智能体决定必填。无参数 UI 的员工执行模板直接验证配置，用已有默认参数或空对象，不打开经营汇总表单；创建/编辑任务直接进入名称与提示词。无报告 UI 使用默认结果界面；员工执行结果统一标记 agent-task，不依赖继承的 Skill 展示类型或结果是否包含会话字段。定制入参存在时仍严格校验 Schema，固定 Skill 未定制时保留原生表单。发布仍须当前 revision 验证通过，所有运行保存 json-result。无需迁移。

2026-10-11 参数验证语义修正（TP-R13）：默认参数可选且可缺少任务必填项；验证请求可显式提供独立 `parameters`，不合并或存入默认值。旧客户端省略该字段仍使用默认值。智能体模板为“配置验证”，不执行模型/工具；真实运行通过任务管理创建任务并运行，保存正式记录。Skill 模板的“试运行”执行既有注册 Skill。发布仍绑定当前 revision 的验证结果，失败撤销验证，修改需重新验证。下方旧默认值试跑描述以此修正为准。

2026-10-11 提交交互修正（TP-R15）：参数沙箱仍仅 allow-scripts，不增加 allow-forms。原生 submit 控件经本地可取消 SubmitEvent 调用页面处理器，宿主继续做 Schema 和服务端校验；普通按钮保持 click 路径。不使用浏览器默认表单导航。参数确认等待提供 5 秒无响应提示；API 验证失败保留表单，成功自动切到发布步骤。最终验证/发布动作常驻底部，发布仍需用户明确点击。

2026-10-11 执行契约纠错（TP-R16）：自定义 UI 不会替换固定 Skill 的 prepare 契约。注册输入校验失败返回可选的 code/target 元数据与有界、无参数值的中文 message，旧客户端仍可读 message。PARAMETER_EXECUTION_MISMATCH 引导回执行配置或参数 UI，不能靠盲目重试解决。明确修改执行方式保留临时验证输入；Schema/input/defaults 改变时清空，发布仍绑定新保存 revision 的验证。普通新建默认配置员工，专门的经营汇总复制保持旧 Skill 语义；不迁移或静默修改现有草稿。

自动化与任务 → 任务管理 → 管理模板 → 新建模板：

1. 基本信息：名称、说明。
2. 输入参数：单一编辑入口，返回时同步有效参数 UI 到草稿；隐藏高级设置、设计员工和默认参数。
3. 执行能力：选择数字员工或已注册的执行 Skill，设置结果存储位置（当前仅任务运行记录）与可覆盖的默认输出要求；Skill 模板保留导出格式配置。
4. 任务报告查看：默认结果界面，按需在独立项目编辑自定义报告；预览、返回同步草稿和明确恢复默认。
5. 试运行与发布：先保存并试运行，检查报告预览，再发布当前版本。

发布后，在“模板任务”选择该模板创建任务。参数会预填，仍可修改。运行后可以查询报告、结构化数据、输入快照，下载已启用的格式。

内置经营汇总模板继续可直接使用。默认参数是固定值，不会自动将月份推进到当前月份。

## 生命周期与数据归属

TP-R18：模板可选 `resultOutput` 默认输出配置、`reportUi` 不可变报告快照，定义可选 `reportProjectId` 与参数项目独立。任务创建时继承输出默认值，显式任务配置优先；每次运行继续保存 json-result。运行结果保存报告快照，历史查看不读取最新草稿。`platform.ready/getResult()` 报告 SDK 只注入当前结果 {title,data}，无业务查询、凭据或提交桥；设计预览明确标注示例。报告文件共享现有快照路径/权限/运行锁/大小保护并校验 JS 语法；iframe 仅 allow-scripts，CSP 禁止网络/表单，报告脚本异常提供可见原始 JSON 回退。新报告项目不自动调用模型，返回同步草稿，不自动发布。新增字段均可选，旧模板无需迁移。

- 自定义模板以当前组织和账号隔离保存到 API 的 domain KV，不使用浏览器本地存储作为事实源。
- 草稿支持保存、继续编辑和复制；修改采用 revision 校验，避免覆盖他人或其他页面的新修改。
- 试运行校验 Skill 入口、契约兼容性、默认参数、执行输出、报告和导出能力。当前注册能力是无外部副作用的经营汇总 Skill；试运行不创建正式任务或运行结果。
- 验证绑定草稿 revision，任何保存修改都会使旧验证失效。只有当前 revision 通过试运行，才允许发布。
- 发布版本从 1.0.0 递增；发布版本不可覆盖。编辑已发布模板生成下一草稿版本，旧任务继续绑定旧版本。
- 停用模板从新建列表隐藏并阻止新建；已有任务仍可编辑参数、执行和查询历史。支持恢复。
- 删除自定义模板须确认并校验 owner/revision；以 deletedAt 墓碑从管理和新建列表隐藏，保留已发布依赖版本及关联项目。已有任务的定时执行、参数编辑和历史结果不受影响。模板管理为任务管理内的次级入口，不再占用顶层 tab。
- 每次运行保存模板、输入、参数版本及结果展示/导出配置快照，历史结果不跟随模板变更。

## 运行与安全约束

- iframe 输入页仅允许脚本，不允许同源和网络，通过 source + 每次编辑 channel 校验消息；界面不持有凭据。用户应用参数后由宿主提交，服务端再次校验。
- 结果 HTML 转义用户内容，报告在无脚本沙箱中展示；CSV 转义单元格并处理业务名称中的公式前缀。
- 金额按分计算，零收入利润率为 null；利润仅为用户输入收入减成本，不代表净利润。
- 服务端验证导出格式策略。隐藏报告明细仅影响展示，不构成数据访问权限限制。
- 请求 ID 避免重试重复执行；服务重启将中断运行标记失败，不自动重放。
- 不兼容的展示模板回退结构化数据。

## 当前范围

配置已经完整接入保存、验证、发布和运行，不是只保存表单的原型。但能力目录目前只有内置经营数据汇总 Skill，输入最多 100 行，结果内联保存于运行记录。

已落地一个可操作的数据库取数闭环：数据工作台和“自动化与任务”均提供“数据库任务闭环体验”入口；首次点击会在当前账号的默认工作库创建 4 条幂等测试记录，客户下拉选项由 `/data/gateway/options` 从该表查询，运行时服务端按当前账号所有权校验读取数据，调用经营汇总 Skill，并将报告与结构化结果写回一个新的“测试结果”数据源。重复初始化不会重复建表；运行请求用 requestId 去重；其他账号不能读取。当前 demo 的字段映射固定为客户编号/客户名称/月份/收入/成本，作为下一步抽象可配置数据能力的参考实现。

尚未支持任意上传执行代码、动态安装 Skill、可视化字段 schema 设计、任意数据库/API 连接配置、外部业务写入及新模板定时调度。原有定时任务单独保留。后续新增能力需实现执行入口、数据契约与能力描述，并显式注册；有副作用能力接入前需要独立的试运行/交付机制。

## 项目编辑参数 UI（2026-10-11）

输入参数步骤仅提供编辑入口及已有界面的草稿/发布状态，隐藏高级适配器、设计员工和默认值设置（保留存量配置）。复用私有项目文件树、流式多轮 AI 对话和预览；项目创建不会启动首轮 AI。明确返回模板时同步最新项目 UI，服务端校验 input.schema.json；相同内容哈希导入幂等，保留 revision 与验证状态，变化内容只更新草稿并撤销验证。可选验证入口及最终验证均先同步再打开测试表单；返回本身不强制弹表单、不自动发布。已有任务仍绑定发布快照。真实查询在模板沙箱中由宿主以当前用户身份调用已列出的数据查询 API，凭据不进入页面。

执行能力可选择现有数字员工及默认提示词，正式任务通过现有智能体编排执行并关联执行会话，记录 JSON 结果。员工模板发布验证只检查参数，不调用真实模型；需要审批时可打开执行会话处理，不自动重放任务。创建任务使用模板卡片 → 独立参数窗口 → 名称/提示词窗口。新模板任务仍为手动执行，原定时自动化保持原有流程。

详细契约与验证：docs/sdd/features/task-template-project-v1/README.md。

## 统一任务定时执行（2026-10-11）

任务管理中的模板任务与直接任务均支持手动、一次性指定时间、固定分钟间隔、每日、每周、每月。`TaskScheduleSchema` 是共享契约；`TemplateTaskService` 持久化计划与下次时间，API 生命周期每15秒触发有界调度，复用原任务执行和员工引擎，不再依赖此页面的 renderer 计时器。任务可按 revision 修改周期或快捷暂停/恢复；立即运行不改变自动计划。每次运行独立记录 trigger/scheduledFor 与 json-result。

任务页面关闭不影响执行，停止服务则停止调度。恢复时不突发补跑全部错过周期；定时触发前持久化领取时点，避免重复，进程恰在领取与创建运行之间中断可能跳过该次执行。相同任务的手动/自动执行串行，周期故障不自动重试。日历周期按指定 IANA 时区，月末日期不足时取最后一天，DST 不存在的时刻跳过当天。本期不提供系统级唤醒、云端执行或多 API 写者调度。旧版 renderer 自动化配置未删除或自动复制到新任务系统。

规格与回归：TP-R11/T11，`task-schedule.test.ts`、`tasks:smoke`（独立 API 计时器，无 renderer/真实模型）、`task-center-browser.mjs`。
