# 数据能力平台与任务闭环

## 决策

OpenClawX 采用“数据工作台、数据网关、任务/Skill”三层模型。

- **数据工作台**是数据控制中心：维护连接、发现元数据、补充业务标注、发布应用数据单元。
- **数据网关**是唯一运行时入口：执行 `options`、`query`、`aggregate`、`write`，统一注入当前登录用户上下文，并记录审计。
- **任务模板与 Skill**只声明需要的应用数据单元和业务结果，不直接连接数据库，不保存凭据。

## 核心对象

### 应用数据单元

应用数据单元是面向任务和应用的数据契约，不是物理表的别名。当前数据对象第一期维护数据集的最新 Schema、业务说明与连接说明，**暂不实现数据 Schema 版本和兼容性管理**。更完整的操作输入、结果结构和写入策略仍按下面的平台目标逐步建设，不代表已经上线。

### 操作 Spec

操作 Spec 是网关可识别、可测试的稳定动作，例如“搜索客户”“查询项目订单”“写入经营结果”。它声明输入、输出、数据集、权限要求、分页、是否有副作用和版本。Spec 是底层能力；Skill 可以组合多个 Spec，描述专业做法。

### Skill

Skill 负责专业流程、业务判断、计算和报告生成。Skill 只能调用已发布的网关操作，不能直连数据库或接收前端伪造的用户身份。

## 用户流程

普通用户只看到：

```text
选择任务 → 选择/搜索业务数据 → 填写参数 → 运行 → 查看结果
```

数据管理员看到：

```text
连接数据源 → 读取元数据 → 补充字段标注 → 生成操作草稿 → 沙箱测试 → 发布数据单元
```

元数据自动生成候选字段类型、主键、关联关系、可搜索字段和输入选项。业务口径、敏感级别、写入方式等必须人工确认后发布。AI 可以提出标注建议，但不能把建议直接变成生产规则。

## 访问与权限的简化规则

第一阶段不建设独立策略语言。所有数据网关调用自动取得当前会话的 `orgId`、`userId`、`role`，数据工作台连接和数据集先做所属权校验，网关再执行数据集范围过滤。前端和模型提交的 userId、orgId、SQL、连接凭据均不可信。

任务只引用已发布的数据单元。查询选项和正式取数使用同一个网关，但分为 `options` 和 `query` 操作；选项只返回 ID、显示名和必要辅助字段，正式运行时再次验证所选 ID。结果集默认继承任务与输入数据的可见范围。

手动运行使用当前登录用户；定时运行暂使用任务所有者，所有者失效时任务暂停并提示重新授权。未来需要服务账号时再增加，不把它提前引入当前版本。

## 数据交换与写入

任务结果使用“统一数据交换信封＋目标 Schema”，而不是自由 JSON：

```json
{
  "dataset": { "id": "business-results", "schemaVersion": "1.0" },
  "operation": "append",
  "run": { "taskId": "task_1", "runId": "run_1" },
  "records": [],
  "metadata": { "currency": "CNY" }
}
```

网关写入负责 Schema 校验、类型/单位转换、主键策略、追加或更新、幂等和回执。外部应用使用字段映射适配器，不让每个 Skill 编写一套入库 API。

## 发布生命周期

```text
元数据草稿 → 操作 Spec 草稿 → 沙箱测试 → 人工确认 → 发布版本 → 被任务/Skill/应用使用
```

上述操作发布生命周期是后续平台目标。数据对象第一期每次保存直接更新当前 Schema，无发布版本、固定旧 Schema、历史回放或兼容性检查。字段 ID 不允许通过标注编辑变更；API 同步按源字段匹配保留 ID 与标注，只是避免重建丢失，不提供结构变化兼容承诺。任务结果契约版本与应用 HTML 修订是独立机制，不受此次范围调整影响。

## 当前闭环

### AI SQL 操作与统一预览（2026-10-13）

本节是数据应用当前增量决策，取代下文 MDA-1 中“仅结构化定义、任意 SQL/写入均不支持”的首版限制；员工一般问数仍走原结构化工具。

AI 直接编写参数化 SQL 及命名参数协议，使用对象表/字段 ID，网关解析 AST、校验对象范围和敏感列后映射可信物理绑定及方言，不重新推导业务查询逻辑。只执行重新序列化的已检查 AST，字符串常量也参数化，避免跨方言引号解释差异；特殊标识符或不支持的 SQL 形式拒绝，旧结构化路径保留。SELECT 测试通过才持久化定义，不保存测试行。

写操作登记时检查原生类型、必填字段与非 ANALYZE EXPLAIN，不实际试写；作为待审核定义保存。所有者管理员查看 SQL 后按定义哈希批准，修改定义撤销批准；模型没有批准/执行写入工具。实际运行通过 mutate 接口，要求当前账号为所有者管理员、对象明确开启写入，审核后的新增/修改/删除直接提交，不逐次弹平台确认。首期限事务实时表单行 INSERT、完整主键等值 WHERE 的 UPDATE/DELETE，不改主键/生成列，影响超过一行回滚。可选事务试写只在管理员确认的测试库执行并回滚，不保证序列/外部副作用还原。SQLite 本地副本 SQL 仅 SELECT；无批量写、自动重试、跨请求幂等或旧值冲突检测。DDL 走下文独立的 MySQL 新表草稿审核流程，不是任意 SQL 执行。

数据项目静态快照入口注入同一无凭据 `openclawxData.query/mutate` SDK，renderer 用当前登录身份桥接；发布页可信登录宿主调用同一数据操作 API。快照票据只允许读静态文件，不授予数据访问。普通静态项目没有 SDK/桥接数据能力，权限、表范围、敏感标记每次在网关核对；预览不需要先发布，也不隐式批准写入。详见 [SQL 规格](../sdd/features/managed-data-app-v1/sql-operations.md)。

### 受控数据应用（MDA-1 基线，限制已由上文 SQL 增量替代）

新建应用采用 `managed-readonly` 模式：对象表集合 → 持续对话项目 → 结构化查询测试/登记 → 页面绑定 → 认证运行。范围在创建时固定；字段说明仍读取最新 Schema，不提供 Schema 版本。服务端持久化查询 AST、参数绑定、验证时间及结果字段，不保存测试结果行或任意模型 SQL。运行时经同一结构化编译器重新生成参数化 SQL。登记失败不覆盖上次有效定义。

应用项目工具从持久化 Run 身份及应用关联派生，不依赖员工全局对象授权；范围不能由模型或页面扩大。页面通过不含身份的 `openclawxData.query` 桥接调用已登记操作。可信宿主持有仅在内存的登录 token，生成页面运行于不带 `allow-same-origin` 的沙箱。查询 API 验证当前登录用户、应用/对象所属权、表范围和敏感字段。发布 token 不授予数据权限，新模式禁止旧 token 数据和 CRUD 接口。当前仅应用所有者可执行，跨用户共享、任意 SQL、写入和自动扩大范围不在首版中。

旧应用不自动迁移。新查询范围表在应用删除后保留非凭据墓碑，确保残留项目不能回退到员工的广域问数权限。查询定义随应用删除清理。详见 `docs/sdd/features/managed-data-app-v1/README.md`。

当前试验版已在数据网关中提供基于数据工作台数据表的：

- 数据单元元数据读取。
- 当前用户所属数据源/数据表校验。
- `options`：按字段搜索并返回 `value / label / description`。
- `query`：按字段过滤、分页读取结构化数据。
- 数据对象说明、连接说明、表说明、字段含义/单位/枚举/敏感标识编辑。
- API URL 与入参/返参标注，JSON 对象/对象数组文件导入。
- `GET /data/gateway/schema`：所属权校验后的最新模型可读 Schema，不含连接密钥和记录样例。
- 应用创建/优化从同一 Schema 组装模块读取说明；API 同步保留已有表 ID、匹配字段标注。
- 新定制应用显式等待页面绑定，绑定后才标记定制交付；不会把模板回退页当作 AI 成果。交付工具与真实 HTTP 取数已做隔离集成验证，真模型端到端验收状态见 [数据应用交付闭环](../sdd/features/data-app-closure-v1/status.md)。
- 数据应用新建入口采用一应用一私有项目，复用 ProjectService / RunEngine、员工授权与所有者上下文；普通对话未改动。SQL 记录稳定 app/project 关联和请求幂等键，确定性项目 ID 恢复半完成准备；不确定启动不会自动重放。数据项目显式启用隔离 Run 工作区、正常完成后晋升固定目录，普通项目默认执行方式兼容保留。优化使用最新 Schema，绑定原应用，旧页面直到新绑定前仍可用。新建模板入口暂停，历史 API/应用保留。详见 [数据应用专属项目第一期](../sdd/features/data-app-project-v1/README.md)。

具体范围与验证见 [数据对象工作台第一期](../sdd/features/data-objects-v1/README.md) 与 [远端数据库接入](../sdd/features/remote-database-v1/README.md)。MySQL/PostgreSQL 已提供管理员只读连接、选库选表、本地快照导入与固定目标刷新；连接密码仅本次请求使用，不持久化。SQL 驱动仅在 API 内部适配层，元数据查询参数化，选表名称按驱动引用且与发现列表核对，使用 READ ONLY 事务。前端/应用仍通过已有网关查询快照，不传原库凭据或任意 SQL；原库写入、跨源联查、操作发布、AI 自动补注未实现。API 也是显式同步到本地后查询，不是任意远端请求代理。

任务参数 UI 已通过受控 `platform.request` 使用技能目录、数据单元、选项和查询接口；专用项目预览使用当前身份测试，返回模板同步草稿。任务结果保留 json-result，可选定制报告只读取运行结果，不继承参数界面的业务查询权限。详见 [任务模板架构](task-template-pilot.md)。上段快照导入的密码不保存；当前实时对象及桌面开发模式的安全存储规则见下文，二者不能混同。

## 非目标

当前不支持任意上传服务器可执行代码、未经登记校验的 SQL、复杂企业级 ABAC、跨组织数据委托、服务账号代理或自动猜测业务指标口径。受控应用 SQL 不等于连接级任意脚本权限。


## 当前统一访问边界

### 本地优先经验记忆（2026-10-13，EX-R1–R7）

save_experience/load_experience不再依赖Embedding启用，agent-core在API宿主执行本地SQLite及JSON卡片持久化，记录可信user/org/agent来源；组织内暂跨用户/智能体检索，组织边界保留。查询资产继续独立、按用户隔离，不将业务SQL自动写入经验。旧经验文件保留并标记未知来源，不擅自归属当前用户/组织。

模型按需保存经验，也可由用户自然语言要求；没有运行成功必然保存的钩子。Pi 每轮用户问题至少4字符且工具可用时预召回一次，AgentScope 仅按需加载，DSH 尚未接入。数据库持久化完成后返回，JSON 副本通过单并发、最多64个待写路径的异步队列落盘，同路径待写更新合并；失败/满载告警不回滚数据库，不等待副本。退出可能丢失待写副本，不承诺数据库慢磁盘零等待。

系统设置选择唯一经验知识库，配置阶段显式测试后才提供available=true；配置指纹变化失效，运行期不探测。远端同步/语义预取有界后台执行，前台只读本地文本匹配或完成的语义缓存，不使用超时竞速换取首token。SQLite为事实源，JSON为副本；远端失败不使本地保存失败。测试连接/检索不保证写入权限，云端提交不冒充索引完成。组织过滤不代替目标知识库自身访问控制，管理员应使用专用库且只保存可共享经验。规格及验证见[本地优先经验](../sdd/features/experience-local-first/README.md)与[状态](../sdd/features/experience-local-first/status.md)。

### 用户主动保存查询资产（2026-10-13，QA-R1–R5）

与agent-core通用经验记忆独立。API在成功查询后生成会话内有界回执（最多5条、7天有效，不含结果行），仅真实用户本轮明确保存/收藏查询时提供保存工具并再次检查意图；模型不能通过SQL参数伪造成功证据或提供授权。保存名称、问题、业务口径备注、定义、参数、对象/表范围和对象Schema指纹，按org/user保存在API单写者domain KV，显式保存/删除等待flush。SQL测试值/默认值不入资产，有原默认值的参数转为必填；结构化筛选保持原值。execution-verified只表示执行成功，不是业务验收。

模型通过名称搜索与只读重新运行复用资产。每次运行重新检查当前运行身份、员工对象关联或应用表范围、敏感标记、Schema指纹，仍经原网关；不缓存业务结果、不扩大权限。SQL资产沿用已有语法限制，应用成功SELECT才产生SQL回执，不新增普通临时任意SQL问数。Schema或业务字段说明变化要求重新查询保存。首期提供宿主Tools及认证列表/删除API，不提供管理UI、自动向量召回、共享或自动Skill生成。明确意图匹配保守，歧义时请用户说“保存这个查询为 名称”；普通对话历史不复制为资产。规格见[查询资产](../sdd/features/agent-data-query-v1/query-assets.md)。

### 数据提示与交付规范分层（2026-10-13，MDA-R13/T23）

`agent-core/data-query-runtime`只按当前工具集合注入数据访问说明，不修改员工基础指令；无数据工具则返回空提示，普通关联对象员工仅问数，应用运行才追加SQL登记与建表草稿指导。Pi/AgentScope共用该入口；具体参数及限制由工具描述和contracts维护，授权与执行仍由API强制校验。工具能力说明不包含npm/CDN/前端入口等交付限制。

API的`app-delivery-prompt`单独维护当前沙箱静态网页的SDK与交付要求，由应用项目背景引用。项目背景不再重复SQL语法/限制清单，当前工具协议优先于历史平台协议，但不覆盖用户业务要求。旧项目背景不自动改写，无存储迁移；此分层不放宽网关或开发宿主能力，也不将静态网页约束推广为智能体全局规则。

### AI 新业务表（2026-10-13，MDA-R12/T22）

数据应用员工可通过 `data_app_propose_schema` 提交 MySQL 新 InnoDB 表及新表索引草稿，不能执行 DDL。独立对象结构创建开关默认关闭；当前所有者管理员在项目“预览与发布”审核规范化 SQL、固定 revision，并明确确认新表加入对象及当前应用后，网关使用已有服务端凭据通道执行。普通 CRUD 写入开关不授予结构权限，其他应用的表范围不变。建表使用真实物理名；成功后重读原库 Schema，生成对象表/字段 ID，后续应用 SQL 仍按对象 ID 登记。

计划及逐条进度保存在 `data_schema_changes`；同对象/连接串行。MySQL DDL 不依赖事务回滚，部分完成和结果未确认分别保留状态，启动恢复不自动重试或删表。首期只支持新建表/索引，不含旧表 ALTER/DROP/TRUNCATE、外键自动登记、PostgreSQL 或本地副本。执行失败后已创建结构需人工核对；不提供自动清理或失败后重新纳入对象的恢复按钮。关闭入口/结构开关不删除已建表。详见 [结构创建规格](../sdd/features/managed-data-app-v1/sql-operations.md)。

### 员工受控问数（2026-10-12）

Pi 与 AgentScope 增加宿主 Tools：发现关联对象、读取安全 Schema、执行结构化查询。数字员工运行设置显式选择对象，默认不关联。API runner 从持久化 RunRecord 取得所有者和组织，宿主异步运行域隔离执行器；工具参数和客户端 context 不携带授权。每次调用复核活跃所有者、私有资源、用户命名空间中的员工最新关联及对象所属权，查询返回前再次复核。共享会话/项目暂禁用；当前不声称支持共享场景的调用者委托。

模型只获得安全业务元数据及最多256KB结果，敏感字段不参与模型查询；仍由既有 SDQ 编译器与 Gateway 执行，不另建 SQL 权限链。DSH 暂不暴露问数工具，不扩大 localhost MCP 桥接能力。历史回答中的数据不会因撤销关联被收回；当前原生 shell/第三方MCP 的已有能力也不在此工具边界中自动消失。详见 [员工问数规格与验证](../sdd/features/agent-data-query-v1/README.md)。

### 单表结构化查询（2026-10-12）

增量 SDQ-v2：同对象显式登记多对一关系后，支持最多三条有向 INNER/LEFT JOIN（不跨对象/连接）。目标组合键唯一性与实际联表匹配数在同一快照中预检，歧义拒绝而非重复累计；指标 filters 通过参数化 CASE WHEN 提供条件聚合。元数据经对象所有者保存，模型只使用登记关系，不可提交 ON 条件。Tools 同步检查关联键/列/指标条件敏感标记。简单查询界面暂不新增关联编辑器，入口及验证见 [SDQ-v2](../sdd/features/structured-data-query-v2/README.md)；以下段落描述 v1 基线。

新增 `POST /data/gateway/query`，旧 GET 保持兼容。输入是严格 Zod 查询描述，不接受 SQL、用户身份或连接凭据；服务端先按当前用户/组织核对对象和表，再由确定性编译器生成参数化 SQL。支持有界 AND/OR、比较/范围/集合/空值/文字筛选、排序、offset 分页、count/sum/avg/min/max/countDistinct、分组、年/月/日日期桶、指标 HAVING。SQLite 本地表和 MySQL/PostgreSQL 实时表共用编译规则；统计在数据库端执行全部匹配记录，行数上限只影响结果输出。

对象详情“查询分析”提供不依赖 AI 的明细、简单筛选和单组单指标统计测试。高级嵌套筛选、多指标、HAVING 通过 API 使用。SDQ 本身是查询基础能力，员工问数通过上文宿主工具接入；仍为 owner/org 范围，不包含多表关联、跨源分析或任意 SQL。结果携带查询 ID/时间/模式，但本期不新增持久化查询审计。SQLite 原生数值精度、分页数据变化及存储日期语义限制见 [SDQ-v1](../sdd/features/structured-data-query-v1/README.md)。

实时数据库对象新增独立连接注册与安全凭据通道。原有 MySQL/PostgreSQL 快照保持“本地副本”，不自动转成实时对象。新实时对象只登记原生绑定与最新业务标注，Gateway 查询才连接原库，缺省只读；开启写入要求对象 owner 且为管理员显式确认。有主键并支持安全事务的表才可修改，写入使用参数化 SQL、行锁及原值冲突校验。密码不进入对象或模型 Schema；桌面由主进程 safeStorage 保存，桌面开发态独立 API 经内部安全桥复用该存储，无桌面的纯 API 模式才仅保存在会话内存。员工只读问数可通过上文工具访问实时对象；新应用实时绑定使用上文 MDA 模式，旧应用路径仍拒绝实时对象。当前规格见 [实时数据库对象](../sdd/features/live-data-objects-v1/README.md)。

任务和数据应用均通过数据工作台所属的数据访问边界执行：先按当前用户、组织和数据表所有权校验，再查询数据。网关单元返回字段 Schema、可用操作和 `owner-scoped` 访问模式；页面只获得业务数据，不接触数据库凭据。当前任务闭环中的客户选项和应用查询已经使用网关查询模型，后续聚合、写入和外部连接器也必须注册为网关操作，禁止业务模块自行拼接 SQL。
