## 一、简介 {#intro}

Workmate 是一个**本地优先**的「数字员工」AI 工作台。你可以把不同的 **AI 数字员工** 当作团队里的同事来使用：与它们对话、把任务交给它们执行，让它们调用 **技能（Skills）**、检索 **知识库**、访问 **MCP 连接**、使用 **联网搜索**，并管理运行产生的 **资产** 与 **自动化** 任务。

整套产品由几部分组成：

| 部分 | 作用 |
| --- | --- |
| 桌面应用（Electron） | 主界面：对话、员工、项目、设置等所有操作入口 |
| 本地 API 服务 | 本地运行的任务编排与状态管理 |
| 通道网关 | 让外部 IM（Telegram / 飞书）与远程终端可以调度你的员工 |
| 模型服务 | DeepSeek、OpenAI、通义千问、GLM 等云端模型，或本机 Ollama |

> 💡 **记住一个核心流程**：先配置模型（Provider + 模型），再与数字员工对话。启动时如果检测到模型未配置，应用会自动弹出指引，点击「去配置」即可直达设置页。

## 二、安装与启动 {#install}

### 2.1 环境要求

- 操作系统：macOS / Windows / Linux
- Node.js ≥ 22（源码方式运行时）
- Python ≥ 3.10（可选，使用 AgentScope Sidecar 执行引擎时）
- Docker（可选，容器化部署时）

### 2.2 三种使用方式

**方式一：桌面安装包（推荐）**

从发布页下载对应平台的安装包并安装。macOS 安装包目前未签名，如果系统阻止启动，请在终端执行：

```bash
xattr -cr "/Applications/Workmate.app"
```

如果应用尚未拖入 `Applications`，也可对下载目录中的 `.app` 执行同样的命令后再打开。

**方式二：npm / CLI（Web Launcher）**

```bash
npm install -g @next-open-ai/workmate
workmate doctor   # 检查本地环境
workmate init     # 初始化配置
workmate start    # 启动 Web 版
```

**方式三：源码开发**

```bash
pnpm install
pnpm dev          # 构建 workspace 包，再拉起 Vite + Electron
```

源码开发默认使用以下本地端口：

- 界面：`127.0.0.1:47831`
- API：`127.0.0.1:47832`

如果通过环境变量覆盖 API 端口，桌面进程、Gateway、反向代理和防火墙规则也应使用同一端口。

### 2.3 首次启动后的建议顺序

1. 完成登录或初始化本地管理员（见 [登录与首次初始化](#login)）。
2. 配置模型服务商与对话模型（见 [模型配置](#model-config)）。
3. 运行一次环境检查，按提示补齐缺失项（见 [环境检查与 dsh](#env-check)）。
4. 开始与数字员工对话（见 [对话工作台](#chat)）。

## 三、登录与首次初始化 {#login}

Workmate 使用本地账号体系。首次启动时：

1. 打开应用，进入登录页。
2. 如果是**第一次使用**，页面会显示「初始化本地管理员」：填写组织标识（orgId）、管理员用户名、显示名与密码，点击「初始化完成」。
3. 之后每次启动只需输入用户名与密码登录。

> 管理员可以在「设置 → 用户管理」中新增、编辑或停用其他本地用户，并分配 `admin` / `member` 角色。

## 四、模型配置 {#model-config}

> 模型配置是使用 Workmate 的**前置条件**。缺少服务商或模型时，启动会弹出引导提示；你也可以随时在「设置 → Provider / 模型」中修改。

![模型配置章节](images/user-manual-2-model-config.png)

*启动引导弹窗中的「📖 查看手册：模型配置」会直接打开手册并定位到本章节。*

### 4.1 配置 Provider（服务商）

1. 打开左侧「设置」，进入 **Provider** 标签页。
2. 点击「新增服务商」，选择类型并填写：
   - **服务商类型**：共支持 10 种——OpenAI、Anthropic（Claude）、Google（Gemini）、DeepSeek、GLM（智谱）、通义千问（Qwen）、火山引擎、科大讯飞、Ollama（本机，无需 API Key）、OpenAI 兼容（任意兼容接口，适合企业网关或自建代理）。
   - **服务类型**：只在需要区分凭证产品线时出现。火山引擎仅提供「综合模型」「语音」两个场景，语音包含识别与实时语音，旧实时连接仍兼容。通义千问和 OpenAI 固定使用综合服务，不展示拆分选项；不同密钥或业务空间需要隔离时另建连接。
   - **API Key**：云端服务需要填写服务商密钥；Ollama 不需要。新增和编辑时默认遮蔽，可点击「显示密钥」核对，再点击「隐藏密钥」；关闭编辑或切换连接/供应商后重新遮蔽，不保存显隐状态。请避开录屏或共享屏幕。
   - **Base URL**：官方地址由系统按厂商、服务类型、地域和业务空间自动生成，普通用户无需填写；只有代理、私有网关或兼容接口需要在高级设置中覆盖。
3. 点击「测试连通」，看到成功提示后再保存。就绪的服务商显示绿色「已就绪」标签，缺少必填项则显示黄色「待完善」。新增连接时可使用 **Provider 自动配置**，按照内置推荐补齐常用模型和缺失的能力绑定；已有手工配置不会被覆盖。
4. 保存后仍可随时点「编辑」修改：切换供应商类型时，默认地址与必填项会自动联动；展开编辑面板还可勾选「禁用思考模式」（对部分推理模型生效，可减少思考过程输出）。

> 删除某个 Provider 时，与之关联的已配置模型会在保存时一并清理，请谨慎操作。

#### 4.1.1 推荐：使用“自动配置”准备完整模型能力

> **推荐优先使用自动配置。** 只保存 Provider 并不代表图片理解、生图、Embedding、语音识别等能力已经可用。“自动配置”会按服务商的可靠预设登记常用模型、补齐缺失的能力绑定，并让当前默认数字员工可以按需调用这些能力，可显著减少漏配和模型类型选错的问题。

有两种使用方式：

1. **新增 Provider 时自动配置**：已适配的服务商保存连接后会直接生成推荐配置，无需额外勾选；OpenAI 兼容等无法可靠推断模型的连接仍进入手工登记。
2. **为已有 Provider 自动配置**：在 Provider 卡片右上角点击“自动配置”。适合以前只配置了对话模型、后来需要补齐图片、向量或语音能力的连接。

自动配置会执行以下操作：

- 根据 Provider 类型创建项目内置且经过适配的推荐模型，例如主对话、图片理解、生图、Embedding、ASR 和 TTS。
- 在没有默认对话模型或默认向量模型时，设置合理的默认项。
- 补齐尚未设置的应用模型能力绑定，并为当前默认数字员工设置“按需使用”。
- **保留已有模型和人工选择**：已有默认模型或能力绑定不会被自动替换，再次执行也不会重复创建相同配置。
- 不会发起付费推理、不会上传业务数据；真正调用模型前仍可逐项修改。

完成后页面会显示新增模型数量和已配置的能力。接下来进入“模型”标签页，对准备使用的模型逐项点击“测试”，确认 API Key、额度、地域和模型权限均正常。自动配置生成的是推荐配置，不能替代服务商侧的开通和授权。

> OpenAI 兼容连接没有统一、可信的模型目录，Workmate 不会猜测模型 ID。这类 Provider 会引导你进入“模型”页手工添加上游实际提供的模型。

2026-10-14：通义图片生成默认改为 `qwen-image-2.0`（DashScope 原生同步协议），图片识别为 `qwen-vl-plus`（OpenAI 兼容协议）；使用公共端点时 Workspace ID 留空即可，仍需匹配地域及模型权限。重新自动配置会补齐新推荐模型，不覆盖已有默认绑定；已有 `qwen-image-3.0` 需在模型/能力默认项中主动切换。火山「语音」只填 API Key 可准备 ASR 与实时语音；旧版 TTS 另需 App ID，填写后再次自动配置可补齐。

#### 4.1.2 API Key 申请入口与特殊配置

下面的链接均指向服务商官方控制台或官方说明页。点击后会在系统浏览器的独立窗口中打开，当前 Workmate Provider 配置页和已录入内容会保留，获取 API Key 后可直接切回继续填写。申请密钥前通常需要登录、完成服务开通，并按服务商要求配置付费方式或可用额度。密钥创建后一般只完整显示一次，请立即妥善保存；不要把密钥粘贴到聊天内容、截图、代码仓库或公开日志中。

| Provider | 官方申请或配置入口 | Workmate 中需要填写 | 特殊要求与常见问题 |
| --- | --- | --- | --- |
| OpenAI | [创建和管理 API Key](https://platform.openai.com/api-keys) | API Key；Base URL 通常保持默认 | API 平台与 ChatGPT 订阅分开计费。团队环境建议创建 Project Key，并确认项目有可用额度及目标模型权限。不要填写权限更高的 Admin Key。 |
| Anthropic（Claude） | [Anthropic Console：API Keys](https://console.anthropic.com/settings/keys) | API Key；Base URL 通常保持默认 | 需要在 Console 中为工作区开通 API 使用与计费。组织成员若无法创建密钥，需要管理员授予相应权限。 |

| DeepSeek | [DeepSeek 开放平台：API Keys](https://platform.deepseek.com/api_keys) | API Key；Base URL 通常保持默认 | 登录开放平台、充值或取得可用额度后创建密钥。网页聊天会员权益不等同于 API 额度。 |
| GLM（智谱） | [智谱开放平台：API Key](https://open.bigmodel.cn/usercenter/apikeys) | API Key；Base URL 通常保持默认 | 普通模型调用使用开放平台 API Key；“编程套餐”等专项 Key 可能使用独立额度与端点，不要混用。 |

| 火山引擎 | [火山方舟：API Key 管理](https://console.volcengine.com/ark/apiKey)；[火山引擎控制台](https://console.volcengine.com/) | 方舟选择“综合模型”；识别与实时语音选择“语音”并填写 API Key；旧版 TTS 另需 App ID | 方舟和语音可能使用不同凭证，分别建立连接，系统按能力派生端点。 |
| 科大讯飞 | [讯飞开放平台控制台](https://console.xfyun.cn/) | 当前主要用于语音能力：API Key、API Secret、App ID | 先在控制台创建应用并开通所需的语音识别或语音合成服务，然后从该应用的接口认证信息中复制三项凭证；不同应用或服务的凭证不能随意混用。 |
| Ollama | [Ollama 下载](https://ollama.com/download)；[模型库](https://ollama.com/search) | 不需要 API Key；默认 Base URL 为本机 Ollama 地址 | 先安装并启动 Ollama，再执行 `ollama pull <模型名>` 下载模型。若 Workmate 与 Ollama 不在同一主机，需要填写可访问的地址，并自行限制网络访问范围。 |

> **通义千问 Workspace ID 怎么填？** 默认不用配置，在 Provider 的“高级连接设置”中保持为空即可。标准模型会使用 API Key 所属的默认业务空间；只有 API Key 属于子业务空间，或调用知识库、调优/专属模型及工作空间隔离资源时才填写。Workmate 会根据所选地域的百炼 Base URL 和 Workspace ID 生成工作空间专属地址。若出现 `InvalidApiKey`、无模型权限或资源不存在，优先检查 API Key、Workspace ID、地域和 Base URL 是否属于同一业务空间。

> **密钥安全建议**：为 Workmate 单独创建最小权限密钥，设置预算、额度或 IP 限制；共享电脑上不要使用个人高权限密钥。密钥疑似泄露时，应先在服务商控制台创建替代密钥并验证，再撤销旧密钥。

### 4.2 添加模型

1. 切到 **模型** 标签页，点击「添加模型」。
2. 选择已就绪的 Provider，再选择**能力**：
   - **chat（对话）**：日常对话与任务执行使用。
   - **quantum-code（量子代码）**：生成受控的量子程序建议。
   - **image（生图）**：图片生成（如 OpenAI 的 `gpt-image-1`）。
   - **vision（图片理解）**：当主对话模型不能看图时，按需识别图片。
   - **embedding（向量化）**：知识库语义检索使用。
   - **asr（语音识别）/ tts（语音合成）**：语音相关能力。
   - **decision（决策判断）**：有限问题分类、评分、路由及工具执行前风险判断。
   - **ontology（本体语义匹配）**：名称和别名规则未命中时，在受限候选范围内识别用户问题对应的业务实体。
3. 填写或从下拉候选中选择 **模型 ID**（如 `deepseek-chat`、`gpt-4.1-mini`、`qwen-plus`）。
4. 多数云端服务商支持「从服务商拉取模型列表」一键导入，比手填更省事。
5. 保存后，模型会出现在可选项里；新添加的对话 / 向量化模型默认自动成为对应能力的默认模型。

> 除主对话模型外，上述专业能力统一称为“应用模型”。模型负责能力，Provider 负责连接与密钥，两者分开管理。

### 4.3 测试模型与健康状态

每个已配置模型都提供「测试」入口。点击后会打开严格模态窗口，测试期间不能误触遮罩关闭：

- 对话、Embedding、量子代码和决策模型使用预设最小请求，并显示结构化结果与耗时。
- 图片生成提供可编辑的预设提示词，成功后直接显示图片。
- 图片理解和语音识别允许上传不超过 2 MB 的测试样本。
- 语音合成成功后可以直接播放生成音频。
- 长时间测试会显示平滑进度、当前阶段和已耗时；真实结果返回前不会提前显示 100%。

测试成功或失败都会更新模型的最近健康状态。失败信息会尽量区分配置错误、权限问题、内容安全拒绝、网络异常和服务临时不可用；测试样本与结果仅用于当前窗口，不会写入资产库。

### 4.4 设置默认模型与应用模型绑定

1. **默认对话模型**：在模型列表中找到目标对话模型，点击「设为默认对话模型」。新建对话默认使用它；对话输入栏右侧的下拉框可临时切换本次对话使用的模型（显示为「服务商 · 模型」）。
2. **默认向量化模型**：embedding 模型通过列表中的单选按钮设为默认，知识库检索会优先使用它。
3. **应用模型默认绑定**：图片、视觉、语音、向量、量子代码、决策和本体语义匹配等能力各自选择默认模型；其中本体语义匹配由知识检索链路按需调用。
4. 在「数字员工」详情页还可以为单个员工指定专属默认模型（见 [数字员工](#employees) 章节）。

### 4.5 决策模型与工具守卫

决策模型也是应用模型。先在「模型」中登记能力为“决策判断”的模型，再进入「设置 → 决策守卫」选择它：

- **关闭**：默认状态，不请求决策服务，也不增加任务延迟。
- **观察**：执行判断并记录结果，但不拦截工具，适合灰度验证。
- **强制**：在工具真正执行前判断风险，高风险或明确拒绝时阻止执行。
- **网络失败策略**：通常选择“自动放行”，避免受限地区或服务不可达时拖慢整个系统；安全优先环境可选择“拒绝执行”。
- **主模型按需调用**：开启后，主模型可以调用同一决策模型完成分类、评分和路由。
- **MCP 对外开放**：当前是预留开关，默认关闭，不会额外启动端口或进程。

JEV 是首个兼容的决策模型，但配置与运行机制不绑定单一厂商，未来可接入同协议或新增适配器的其他决策模型。

## 五、对话工作台 {#chat}

「对话工作台」是 Workmate 的主界面，用于与数字员工对话、安排任务。

![对话工作台章节](images/user-manual-3-chat.png)

### 5.1 新建对话

1. 点击左侧「新建对话」按钮。
2. 在顶部选择要对话的数字员工（每个员工的职责与模型偏好不同）。
3. 在输入框输入内容，回车发送。

### 5.2 对话能力

- **在线搜索**：发送前可勾选「联网搜索」，让员工先检索再回答。
- **协作调度**：支持一次邀请多个员工共同完成复杂任务（按需使用）。
- **自动化调度**：对话中的任务可交给自动化定时执行（见 [自动化](#automations)）。
- **权限档位**：可在对话中调整本次运行的权限级别（只读 / 默认 / 扩展 / 完整）。
- **图片输入**：添加图片后，视觉主模型可直接理解；否则由已启用的图片理解应用模型按需识别。
- **语音输入**：上传录音后，可调用已启用的语音识别应用模型转写。
- **文档与演示附件**：支持 PDF、DOCX、PPTX、PPSX、HTML/HTM、Markdown 和 TXT。PDF/Word/PowerPoint 在本机解析；HTML 会安全提取标题和正文并过滤脚本、样式；演示文稿会按页提取正文、表格文字和演讲者备注，并根据本轮问题选择相关页面。
- **表格附件**：支持 XLSX、XLS 和 CSV。系统读取工作表结构和有限行预览，避免把整本大型工作簿塞入模型上下文。
- **专业模型工具**：员工会按任务需要调用生图、语音合成、Embedding、量子代码或决策模型，无需手工切换主对话模型。

附件入口统一位于输入框左下角的回形针菜单，也可以把文件直接拖入输入框。单次最多 10 个附件、4 张图片、1 个音频、3 个演示文稿，总计不超过 50 MB；单个 PPTX/PPSX 最大 25 MB、最多 300 页，HTML/HTM、Markdown 和 TXT 单文件最大 2 MB。界面会显示解析状态、文件类型、页数和摘要。旧版 `.ppt` 暂不支持，可先在 PowerPoint/WPS 中另存为 `.pptx`。

对话附件默认只是临时文件，**不会自动进入资产库、知识库或数据工作台**。消息发送后可在附件卡片中主动选择“保存资产”；表格还可主动选择“导入数据”。知识库导入需要进入知识库并选择目标库、向量模型和分片配置。

#### 5.2.1 实时语音与语音输入

实时语音不再单独填写密钥，也不再提供独立语音设置页：在「Provider 与模型」配置统一连接和实时模型即可。火山引擎选择「语音」，系统准备 ASR 与 SeedDuplex 模型及音色；旧“实时语音”连接保持可用。通义综合连接可登记 `qwen-audio-3.1-realtime-plus` 或 `qwen3.8-omni-flash-realtime`，按能力派生 WebSocket 地址与音色；Omni Realtime 可在高级设置填写业务空间 ID。“模型”页统一提供通话策略、工作关联、声音表现与完整通话测试。旧火山密钥迁移仍保留回滚来源。

两家供应商均可通过 Function Calling 调度 Workmate 工作能力。阿里实时模型的原生联网搜索不能与工具调用同时启用，因此 Workmate 使用自己的联网搜索 Tool，避免实时会话丢失智能体能力。当前内置音色复刻训练面板仍属于火山专属能力；阿里复刻音色需先在百炼创建，再把返回的音色 ID 填入实时模型配置。

通话状态条会显示实际 Provider、模型和用量。阿里结算帧提供 Token 或字符时显示上游真实计量；火山或其他未返回 usage 的会话显示本地统计的输入/输出 PCM 音频时长，并明确标注“本地计时”。Workmate 不依据易变化的公开单价自动生成货币账单，最终费用仍以供应商控制台账单为准。

输入框左下角的语音入口提供两种相互独立的能力：

- **实时对话**：与当前数字员工进行双向语音交流，可在当前会话启动工作。关联工作完成后会播放一次不超过 50 字的简短通知，并提示到关联对话查看完整成果；不会朗读整份报告。
- **首次启动**：先授权并准备麦克风，再等待语音模型确认配置就绪后开始收音；界面分别显示麦克风准备、模型就绪和收音阶段。连接初始化最长等待约25秒，失败会释放设备并提示阶段，不自动重复上传语音或提交工作。任务完成通知只发送用户可听的正文，不拼接客户端播报控制指令。
- **打断回答（桌面）**：正常插话交给实时语音供应商判断，Workmate只同步停止旧播放、清空排队音频，不再自行用音量或文字判定插话。明确说“停止朗读”“不要继续播报”等时，由语音模型调用播报控制桥停止当前响应，不取消文件生成或分析等后台工作；也可点击“打断回答”立即停播。系统仍请求回声消除，但效果取决于设备；扬声器回声被供应商误判时可使用耳机。通话和已有工作不因普通插话而取消。
- **语音输入**：只把录音转成输入框文字，确认后再发送，不自动启动数字员工任务。
- **字幕**：收起时只显示最新一句，不自动轮播；点击“展开字幕”查看本次通话完整内容。
- **静音与长时间无声**：手动静音立即停止上传；持续约 5 秒没有有效声音时自动进入上游静音状态，恢复说话后自动继续，减少无效音频与异常静音错误。
- **兼容回退**：实时对话优先使用 Provider/模型配置，语音输入仍保持独立能力边界；本机语音通知失败时回退内置提示音，旧配置仍可兼容读取。

手机扫码弹窗提供三类入口：HTTP 快速连接用于文字、任务同步和文件上传；HTTPS 安全连接支持麦克风实时语音；首次使用自签名 HTTPS 时按证书安装说明完成信任。HTTP 不会绕过浏览器安全规则开启麦克风。

### 5.3 持续任务与跨轮续作

#### 查找以前的工作成果

可以直接问“刚才生成的PDF在哪里？”或“找一下以前的海边度假攻略”，不必记住文件名。开启实时语音工作关联后，语音与Pi/AgentScope普通智能体共用只读成果检索：当前对话优先，再按需查历史。系统将有权限的候选名称、时间及关联对话简短摘要交给当前文字模型作语义筛选，再按真实ID读取正文。普通执行使用本轮模型；实时语音使用关联员工配置的文字模型，不额外配置检索模型或向量库。非空搜索最多增加一次模型请求，会产生相应调用费用；文件正文不会在筛选阶段批量发送。语音界面显示名称、时间、类型/状态及打开、下载按钮；多个候选时告诉智能体你要哪一个。

语义模型请求最长等待12秒，应用不额外重试；模型未配置、超时或响应异常时，会明确显示“语义筛选暂不可用”，并保留关键词匹配结果。这不表示成果不存在，可以换关键词或打开原对话核对。当前对话未命中也不能说明历史没有成果。

正文读取统一支持PDF、Word（DOCX）、PPT（PPTX/PPSX）、文本/Markdown、HTML及CSV/Excel表格。资产读取最多10MB、前20页、16000字符；中文字体映射随应用本地携带。表格为每张表前100行预览，有截断会明确提示；HTML只提取正文，不执行脚本。截断、空文字、解析异常、格式不支持、文件已移除和权限失败分别说明，空文字不直接等于扫描件。

基础读取不启动员工，也不消耗新的模型调用。模型判断复杂处理或读取失败需要进一步尝试时，会通过通用委托把原文档副本交给当前员工；员工可调用同一文档服务或已授权Skill。语音桥接不再自行决定如何解析和自动派单。你已明确要求读取时，不必为同一目标再次确认；新授权、额外付费或上传第三方仍须确认。“员工已接受”只代表接手，完整结果在关联对话，完成后可继续问“读取刚才的处理结果”。不打断已有任务，不自动安装/授权Skill或重新生成原文件，OCR依赖已有Skill及配置。

上传附件、资产读取及本地知识库文件导入共用文档能力；附件沿用各格式大小限制，本地知识库文件最多25MB、300页、50万字符，超范围提示拆分，不会默默把截断内容当成完整知识入库。员工的read_document工具只能读取当前工作区，不能访问任意磁盘路径。普通非语音创建的运行也能查状态，省略任务ID可查看当前对话最新工作；非法ID提示先搜索，不直接显示UUID校验数组。

只查询当前账号的归档资产及私有对话关联Run，不扫描电脑磁盘；新工具暂不在共享对话/项目及DSH中开放，不索引任意未归档文件、项目草稿或任务中心独立json-result。历史对话候选扫描有界，返回截断时请缩小关键词；不能将首批空结果当作全量历史不存在。打开/下载仍沿用登录权限，由你点击；不会因为查询旧成果再次播报“新任务完成”。

当消息包含文件并要求生成、转换或处理较复杂的交付物，或明确说明要分阶段完成时，Workmate 会自动把本轮升级为「持续任务」。普通问答不会创建持续任务。

- 未完成任务会在该任务最近一条 AI 记录的下方显示紧凑状态卡片；如果本轮生成了资产，卡片位于资产下方，不占用输入区。状态色点可快速区分执行中、等待、暂停和异常。
- 触发持续任务后，本轮经过校验的原始上传文件会保存为任务源文件；未触发持续任务的普通附件问答仍使用临时附件，不额外占用任务空间。
- 每次运行仍使用隔离工作区；运行结束（包括失败或取消）后，系统会保存安全的工作文件和检查点。
- 后续输入“继续”“恢复”或“完成剩余部分”，系统会恢复最近一个可续作任务，并把上次文件放入本轮的 `.task/` 工作区供数字员工复用。
- 数字员工在 `.task/` 中更新的脚本、状态和中间文件会回写任务检查点，下一次续作读取的是最新版本。
- 当一次运行成功、没有失败步骤，且已经产出交付物或明确说明整体完成时，系统会自动结束持续任务并收起卡片；仍有失败步骤、未完成事项或下一步工作时保留卡片。点击“继续”会立即提交一条可见的续作指令并启动新运行；也可暂停或手动结束任务。
- 等待、暂停或失败的持续任务不会自动绑定到后续普通问题；只有点击“继续”或明确输入继续、恢复、重试等续作意图时才会重新关联。历史上已经存在交付物且最新检查点没有未完成提示的遗留任务，会在读取时自动收敛为完成并隐藏卡片。
- 已归档的产物仍由资产库长期保管；持续任务只保存资产引用，因此中途归档不会妨碍后续运行。

对话中的「执行过程」默认保持紧凑。遇到 Bash 步骤时，点击状态标签旁的箭头可展开本次命令、输出或错误；入口不会额外占用一行。敏感凭据会自动脱敏，过长内容会截断。用户暂停运行时，步骤会明确标记为随本次运行中止，避免误认为编码器自然失败。长时间没有终端输出的视频编码、文件转换等任务不会被界面自动取消。数字员工整轮运行默认超时为 30 分钟，原来保存的 10 分钟默认值会自动升级；其他用户自定义值保持不变。界面会等待完整的运行预算并预留两分钟结算时间，不再使用独立的 12 分钟截止线。超时会明确显示为“运行超时”，不会误报成用户中止。

### 5.4 会话管理

- **继续/切换会话**：左侧「最近对话」列表点击即可切换；工具审批、运行结果都会同步到服务端。
- **清空对话**：点击对话右上角「清空当前对话内容」会清除可见消息、滚动记忆、当前运行记录与临时附件，并把当前任务解除为活动任务；Session 身份、关联资产、持续任务检查点、所有权和长期授权仍然保留，因此该 Session 继续显示在「最近对话」中并可重新使用。
- **删除 Session**：只有在最近对话列表中明确点击 `×` 删除时，才会彻底删除 Session、持续任务工作区和临时数据。清空与删除是两个不同操作。
- **删除对话**：在最近对话列表中悬停会话条目，点击 `×` 删除。
- **临时附件清理**：未发送附件默认保留 24 小时，已发送附件默认保留 30 天；删除对话会同步删除临时附件。可在「设置 → 通用 → 对话临时附件」查看占用、预览清理并清理过期文件。
- **存储清理**：在「设置 → 通用 → 存储清理」点击“扫描空间”，可查看 7 天前的无主运行目录、已结束普通运行的中间文件，以及没有资产记录的孤儿目录。管理员可一键安全清理这些内容；持续任务工作区、正在运行的任务和正式资产不会被自动删除。
- **大资产整理**：扫描结果会单独列出 20 MB 以上的当前用户资产。大资产必须手动勾选并二次确认后才会永久删除，不包含在“一键安全清理”中。
- **手机扫码继续**：对话页提供二维码，手机扫码后可跨设备继续同一会话。二维码约 8 小时有效，手机与电脑需能通过当前局域网地址互相访问。
- **手机传文件到电脑**：扫码页面顶部点击「传文件」，选择文件后上传。文件默认保存到电脑的“下载”目录，不可写时回退到“文档”目录；单文件最大 20 MB，同名文件不会覆盖。

### 5.5 工具审批

数字员工执行过程中如果需要调用敏感工具（写文件、执行脚本、发消息等），对话会停在「等待审批」状态：

1. 查看请求的工具与参数。
2. 选择「允许一次」/「允许本次运行全部」或「拒绝」。
3. 批准后任务自动继续执行，无需重新发起。

## 六、数字员工 {#employees}

数字员工是任务的执行主体。每个员工可以有自己的名字、头像、职责说明、默认模型与技能组合。

### 6.1 创建员工

1. 打开左侧「数字员工」。
2. 点击「新建员工」。
3. 填写名称、头像（可选）、职责描述，选择默认模型与权限档位。
4. 保存后即可在对话工作台中选择该员工。

### 6.2 编辑与维护

- **编辑**：在员工详情页修改资料、模型、权限。
- **绑定技能/MCP**：给员工勾选可用的 Skills 与 MCP 连接器，员工执行任务时才有对应能力。
- **使用应用模型**：每位员工只需一个总开关。默认开启；开启后自动获得已配置且可用的图片、视觉、语音、向量和其他专业模型，由员工按任务需要选择。关闭后不会向该员工暴露这些能力。
- **重置**：恢复该员工的系统默认配置。
- **删除**：移除自定义员工；系统预置员工不可删除。

### 6.3 权限档位说明

| 档位 | 说明 |
| --- | --- |
| read-only | 只读：不能写文件、执行脚本、调用外部工具 |
| default | 默认：常规操作 |
| extended | 扩展：更多工具权限 |
| full | 完整：放开大多数敏感操作 |

### 6.4 经验保存与加载

经验是可复用的简短方法卡，包含适用场景、有效做法、踩坑点、不适用情况与标签，不是完整聊天记录，也不是已验收的业务结论。

- **保存**：智能体发现值得复用的复杂任务经验时，可以主动调用 `save_experience`；你也可明确说“把这次解决方法保存为经验”。不是每轮成功都会自动保存，简单问答通常不保存。
- **加载**：Pi 每轮开始前会根据本轮问题自动检索一次（用户文字至少4个字符且经验功能可用）；Pi / AgentScope 也可按需调用 `load_experience`，例如“查找以前处理类似问题的经验”。AgentScope 尚无自动预召回，DSH 尚未接入。
- **本地优先**：先保存 SQLite 数据库，再后台写 JSON 文件副本；返回保存成功不代表副本或知识库同步已完成。副本写入失败、磁盘慢或队列满不阻塞经验工具返回，数据库持久化本身仍需完成。进程退出可能丢失待写副本，但已保存的数据库经验仍保留。
- **共享范围**：记录用户、组织、智能体和时间；当前同组织内加载不区分用户或智能体，组织之间隔离。不要保存密码、私人信息、业务明细或原始日志；经验内容仅作参考，不增加权限。
- **检索方式**：默认本地文本匹配，不需要 Embedding。知识库配置可用时后台预取语义结果，后续同查询可使用缓存；本次回答不等待远端。配置见 [经验知识库设置](#experience-settings)。

数据库查询需要复用时，请使用 [可信查询资产](#query-assets)，不要把 SQL 或业务结果当作普通经验自动收集。

## 七、技能与连接 {#capabilities}

「技能与连接」集中管理员工的工具箱：技能（Skills）、MCP 连接器与知识库入口。

### 7.1 技能目录与安装

1. 打开「技能与连接」。

## 八、知识库 {#knowledge}

知识库让数字员工在回答与执行时能引用你的私有资料。

![知识库章节](images/user-manual-4-knowledge.png)

### 8.1 创建知识库

1. 打开左侧「知识库」。
2. 点击「新建知识库」，填写名称与描述。
3. 选择向量化服务商：云端（如百炼）或本地 Embedding（需要在设置中配置）。

### 8.2 导入文档

1. 选中知识库，进入「文档」标签页。
2. 点击「导入文档」，上传或粘贴内容。支持文本、Markdown、PDF、DOCX、PPTX/PPSX；PPTX/PPSX 需要已安装增强解析组件，扫描版 PDF 需要支持 OCR 的增强解析组件。
3. 系统先将非 JSON 文档解析为带页码/段落结构的正文，再自动切分（chunk）并向量化，完成后显示文档与分块统计。

### 8.3 检索与问答

- 在知识库详情中可执行**检索测试**：输入问题，查看命中的分块与相似度。
- 员工对话时如配置了知识库引用，回答会自动带出相关上下文。
- 可在「设置 → 知识库」中管理服务商与默认知识库。

### 8.4 构建与发布本体

进入知识库详情的「本体」标签页，依次完成“选择资料—AI 识别—整理候选—图谱审核—发布版本”。未完成前一步时，后续步骤不可越级进入。

- AI 识别任务会保存进度与结果；关闭页面后可以恢复查看。若本地服务重启，运行中的调用会安全停止并保留失败记录，可重新发起，不会显示成仍在运行。
- 候选可编辑实体名称、类型、别名和扩展属性，也可调整关系名称及两端实体；原文证据保持只读，避免审核时改变事实来源。
- 批量接受或拒绝前必须再次确认；批量接受中包含低于 70% 置信度的候选时会额外警告。
- 图谱治理负责处理重复、命名、孤立实体和异常关系。阻断问题未清零时不能发布。
- 发布和版本回滚仅允许管理员操作，发布人由当前登录账户自动记录，普通成员可完成识别、整理和审核并等待管理员发布。
- 发布后，数字员工的 `kb_search` 会默认使用本体扩展、图谱证据与向量结果融合；在知识库编辑窗口可单独关闭“本体增强检索”。本体为空、损坏或暂时不可用时会自动退回普通检索，不影响对话继续执行。
- 可在「设置 → 模型」添加并默认绑定“本体语义匹配”应用模型。名称/别名规则未命中时，系统最多发送 60 个受限候选供模型消歧；模型只能选择已有实体 ID，置信度低于 72%、超时或输出非法时不采用，也不会阻断原始检索。
- Word、PPT、PDF 等文档导入知识库后，与普通文本使用同一条本体构建链路：正文解析 → 知识切片 → AI 候选抽取 → 原文证据核验 → 人工审核 → 管理员发布。图片或扫描内容只有在解析组件能够 OCR/识别时才会进入抽取。

## 十、数据工作台 {#data}

数据工作台以数据对象组织文件、本地/远端数据库与 API，补充供 AI 理解的结构说明后，再创建数据应用。

### 10.1 接入数据源

1. 打开左侧「数据工作台」。
2. 点击顶部「接入数据」：
   - **Excel / CSV**：导入工作簿或表格，每个工作表对应一张表。
   - **SQLite**：导入数据库文件；本地数据库分类中也可新建数据库。导入的是隔离副本，不改原库。
   - **MySQL / PostgreSQL 实时连接**：管理员点击「数据库连接」，新建并测试保存连接，再选库、读取并勾选业务表，创建实时数据对象。连接可以复用，默认只读、不复制业务数据。桌面版及桌面开发模式通过主进程系统安全存储保存密码，重启后可重新读取；不带桌面的纯 API 模式仅在会话内存保留。此前仅保存在内存且已丢失的密码需补填一次，安全存储异常不会降级为明文。TLS 默认开启并校验证书。
   - **数据库本地副本**：「接入数据 → 导入数据库本地副本」保留原快照方式；不会自动变为实时连接。
   - **JSON**：导入一个对象或非空对象数组；嵌套值保留为 JSON 文本。
   - **API**：配置接口地址、请求方式与鉴权，显式同步后查询本地数据。不是前端直连远端 API。
3. 选择数据对象，依次使用「对象说明」「字段说明」「数据预览」「应用」。目录可按名称、类型或业务说明搜索；对象详情会建议下一步，说明未填完整也可以创建应用。文件限制为 8 MB、最多 20,000 行；JSON/API 当前发现前 200 条中的最多 40 个顶层字段。

**实时对象**：在「数据测试」中查询原库数据，最多返回 100 条；对象所有者中的管理员可点击「开启写入…」并确认后使用新增、修改、删除，操作直接作用于原库。这个数据测试界面每次写入仍需确认，与下文审核后直接提交的数据应用不同。有主键、支持事务且字段可安全比较的表才开放测试写入；MySQL 非 InnoDB 表保持只读。修改遇到并发冲突或记录凭证过期时先刷新；提交断线时先核对原库，勿直接重复提交。随时可恢复只读。实时对象支持经审核的 SQL 数据应用写入，不开放旧版 token CRUD 应用生成。对象开启写入不会自动批准应用中的 SQL。

**本地副本**：已有快照保留不变，目录明确标注「本地副本」。每次最多 20 张表、每表 20,000 行、合计 20 MB，超出行数会明确提示截断。在对象详情点击「刷新快照」并再次输入密码，可更新数据且保留人工标注；快照连接密码不保存。刷新会替换副本中的数据，应先保留本地修改；失败保留旧快照。应用中的新增、编辑、删除仅影响副本，**不回写原库**。

在「对象说明」点击「编辑说明」，保存业务用途、来源、更新方式和使用限制；不要填写密钥。API 对象还可标注 URL、query/path/header/body 入参与 response 返参，嵌套路径例如 `data.items[].amount`。标注只是结构说明，不会自动改变实际请求。

在「字段说明」选择表并点击「编辑字段说明」：可编辑表说明、列名称和说明；「更多标注」可填写单位、枚举与敏感标识。敏感标识隐藏 AI 创建应用时的样例，不替代访问权限。每次保存使用最新 Schema，暂不维护 Schema 版本、历史或兼容性。

「查看模型可读 Schema」可以检查 AI 实际读取的结构与说明，不包含认证信息或记录样例。

#### 查询分析

在数据对象详情点击「查询分析」，选择业务表，无须编写 SQL 或调用 AI：

- **明细查询**：选择返回字段，添加筛选条件，可组合“满足全部/任一条件”，设置排序和每页条数后点击「执行查询」。
- **统计汇总**：选择计数、求和、平均值、最小/最大值或去重计数，可按一个字段分组，日期字段可按年/月/日统计。统计覆盖全部匹配记录，而不是仅对当前页求和。
- 每页最多 200 条，可上一页/下一页；更改条件后须重新查询。分页期间原数据变化可能影响结果，超过 10,000 条偏移时请缩小筛选范围。
- 界面显示查询成功、空结果或可重试错误，并标明实时原库/本地数据。只执行查询，不改变原库只读/写入策略。API 对象查询的是最近一次同步的本地副本，不直连远端 API。
- 网关还支持多指标、HAVING、排序加 limit 的 Top N、条件聚合，以及同对象已登记多对一关系的 INNER/LEFT JOIN（最多3条关系）。简单界面不提供完整的关系编辑器或所有高级组合；高级能力通过网关 API / 智能体工具使用，不表示可跨对象或跨数据库任意联表。
- 数值/布尔空白按 NULL 处理；本地日期使用 ISO 格式（如 `2026-09-01`），按存储日期分组，不自动转换用户时区。无效类型数据需修正后再统计。SQLite 使用原生整数/浮点精度，高精度财务核算应核对原库口径。

#### 在对话中问数

1. 打开「数字员工」→ 选择员工 → 运行设置中的「数据问数」。勾选允许此员工查询的数据对象，然后点击本区域的「保存数据关联」；显示保存成功后生效。不选并保存则关闭，不依赖整页运行设置的保存按钮。
2. 使用 Pi 或 AgentScope 引擎，在私有对话或私有项目中选择该员工，直接提问，例如“按客户统计九月份收入，列出前十名”。员工通过受控工具发现对象、读取最新字段说明并查询，不需要填写 SQL 或数据库密码。
3. 关联仅允许只读查询，不能访问该用户其他未关联对象。敏感字段不提供给模型，也不能用于筛选或统计。共享会话／项目暂不开放问数，DSH 暂不提供问数工具。
4. 查询内容将发送给当前员工使用的模型，并进入对话记录。请只关联适合由该模型处理的数据；清空关联并保存可阻止后续调用，但不能收回历史回答中的内容。
5. 回答应注明对象／表、时间范围与统计口径、查询时间；本地副本仅覆盖已导入记录。若缺少字段、连接或权限，请按错误提示修改，不应让员工通过文件扫描等方式绕过。

#### 可信查询资产 {#query-assets}

查询成功后，如果以后还要复用，可明确说：“保存这个查询为 九月收入分析”。只有你明确要求保存或收藏时才保存，不会自动收藏每次查询。

- 支持成功的普通结构化查询，以及数据应用已成功执行的 SELECT；保存名称、问题、统计口径、参数和查询定义，不保存结果明细，也不自动生成 Skill。
- 之后可说“查找名为九月收入分析的查询资产并运行”。每次运行都按当前账号、员工关联、应用范围、敏感字段和 Schema 重新检查，不因收藏而永久取得权限。
- 结构化查询保留原筛选值，不能通过运行参数任意覆盖；SQL 资产不保留测试值或默认参数值，需要按参数定义提供本次值。执行成功只证明查询能执行，不代表业务口径已验收。
- 资产按用户和组织隔离，尚无专门管理界面、共享、自动语义召回或连接级任意 SQL 问数。保存依据是同一私有会话最近成功查询回执（最多5条、7天有效）；过期或 Schema 变化时先重新查询再保存。

### 10.2 生成数据应用

1. 选中数据对象后点击「创建应用」。默认使用当前数据对象中的全部表，无须选择单张主要表；支持本地数据、本地副本及实时数据库对象。
2. 填写应用需求，点击「创建并开始」。应用名称可留空，需求可点击「填入示例后修改」。无需选择应用类型，AI 根据你的描述和数据内容设计界面与交互。本期不再提供新建模板入口，已有模板应用仍可使用。
3. 系统建立应用专属持续对话项目，直接使用选中员工，不创建 DAG；后续通过「编辑应用」进入原项目继续修改。创建失败保留输入，原内容重试不会重复创建；准备完成但启动失败时在原项目继续，列表刷新失败时不要重复创建。
4. AI 优先读取数据对象保存的 Schema，按相关表分页取得字段与业务说明；确有不足时只补查已绑定实时表的原生元数据，不扫描全库或自动扩大范围。AI 可直接生成参数化 SQL，由服务端网关校验、测试并登记，页面通过 `workmateData.query` / `workmateData.mutate` 调用已登记操作。数据库凭据不进入网页。历史结构化查询仍兼容。
5. 在项目「预览与发布」即可验证真实数据，无须先发布：数据应用预览通过当前登录宿主访问网关。普通静态项目没有数据 SDK。发布页需所有者账号登录，链接和二维码不授予数据权限，不支持其他用户借用创建者身份。

AI 定制应用在页面尚未绑定时显示「待交付」，不显示分享二维码，也不会用模板页替代定制成果。项目执行完成不等于页面可用，实际绑定后才显示「定制应用 · 可用」。通过「编辑应用」继续制作或修改，后续执行失败不会覆盖已交付页面。项目使用固定成果目录，隔离工作区成功后晋升；失败轮次已落盘的文本可作为只读草稿查看，未完成的写入分片不显示成成果。应用列表显示创建时间、已绑定页面修改时间，默认最近修改优先，也可按最新创建或名称排序；项目未交付草稿不冒充已交付版本的更新时间，同名卡片不代表同一应用的历史版本。「手机访问与分享」默认收起，删除在「更多」中。

从创建/优化对话返回数据工作台，会回到离开时的数据对象、选中的表和页签，并重新读取最新应用状态；无需重新寻找对象。目录搜索也在本次登录期间保留。点击刷新不会切回第一张表；对象已删除时返回目录并提示。注销、切换用户或重启后不保留这些导航位置，不缓存业务数据或连接凭证。

### 10.3 让应用支持新增、修改和删除

1. 由对象所有者管理员在「数据测试 → 开启写入…」允许这个实时对象写入；数据库账号本身也必须有对应权限。
2. 在「编辑应用」中说明需要的操作，让 AI 生成页面及参数化 INSERT / UPDATE / DELETE。登记时先检查字段类型、必填值和数据库 EXPLAIN，不执行真实写入；错误需修正后重新登记。
3. 打开项目「预览与发布」，核对操作摘要与 SQL，点击审核启用。批准绑定当前 SQL 定义，修改 SQL 后需重新审核；开启对象写入与审核应用操作是两个独立步骤。
4. 已审核且对象允许写入时，页面提交新增、保存或删除直接经网关执行，平台不再逐次弹确认。后台仍检查账号、对象权限、批准版本和参数，不是绕过数据库约束。生成页面应通过 `workmateData.getAccess()` 获取状态，不要写死“只读／待审核”提示。

当前 SQL 写入仅用于实时对象的事务表：单行 INSERT、按完整主键定位的 UPDATE / DELETE，不修改主键、不批量写入；本地副本的新 SQL 应用保持只读。普通员工问数工具仍是只读，不能执行这些写入。

**可选验证**：审核后在「事务试写（仅测试库）」填写测试参数，确认风险后执行并回滚。只在测试库使用；检测到触发器会拒绝，但自增号、序列或外部副作用未必恢复，不能把它当作生产库“完全无痕”验证。默认静态与 EXPLAIN 通过也不等于真实写入成功。

**失败处理**：明确的数据库拒绝会提示重复键、必填项、字段长度或 BIT 类型等原因；显示“写入结果未确认”时，可能已执行但回执丢失，先刷新核对，不要自动重试或重复提交。当前没有跨请求幂等保障。

### 10.4 新业务需要增加表

目前支持 MySQL 实时对象新增 InnoDB 表和新表索引：让 AI 提出建表方案，再到项目「预览与发布 → 新业务表」由管理员开启独立的「结构创建」权限，审核 SQL 并确认创建及纳入当前对象与应用。AI 只提交草稿，不能自行执行建表。

成功后读取真实 Schema 并加入当前对象及当前应用，其他应用不自动扩表，CRUD 写入开关也不自动开启。首期不支持 PostgreSQL、本地副本、修改或删除旧表、自动登记外键关系。MySQL DDL 可能立即提交，部分失败或结果未确认时需人工核对，不自动回滚、删表或重试。

### 10.5 打开、分享与应用大厅

- 数据对象的「应用」卡片提供「打开应用」「编辑应用」，不再提供重复的「继续优化」。展开「手机访问与分享」查看 URL 与二维码；手机需能连接运行 Workmate 的电脑，链接不自动发布到互联网。
- 点击 Workmate 左上角品牌图标打开全窗口「应用大厅」，以卡片展示当前账号已发布、可交付的数据应用；支持搜索、最近更新／最新创建／名称排序、打开和分享。返回后保留原工作台界面。
- 大厅不收录待交付、未发布或无有效 URL 的应用，也暂不收录普通项目静态发布快照。二维码优先使用局域网地址，没有可用地址会提示仅本机可访问；localhost 不能作为手机访问地址。

## 十一、任务中心 {#automations}

「自动化与任务」提供「任务应用」「任务管理」「任务运行记录」。已移除旧的模板管理、模板选择和从模板创建任务流程。已有任务、应用版本、计划及运行记录不会因此删除。

### 11.1 创建任务应用

在「任务应用」点击「创建任务应用」，填写名称、任务目标及执行智能体，再进入项目编辑器，用 AI 多轮设计参数界面。项目中的 `TASK-API-REFERENCE.json`、`API-REFERENCE.json` 和 `DATA-CATALOG.json` 提供任务接口、当前可用数据接口及字段参考；它们不授予额外权限，页面不保存凭据或实现定时器。

编辑后点击「返回任务中心」，有效页面导入应用草稿。填写验证参数、点击「下一步」，校验通过后明确「验证并发布」。验证与发布不执行智能体、不创建任务；失败保留填写内容和具体原因。

打开已发布应用后，先在全屏页面填写参数，点击「下一步」进入独立的执行设置。设置任务名称和执行时间，选择「立即执行」或「保存定时任务」；可返回上一步修改，输入保留。只有明确执行或保存计划才创建任务，参数确认与切换步骤不会开跑。提交成功进入运行记录。首版应用在已登录任务中心使用，不是公开网页链接。

### 11.2 管理任务：编辑、再次运行和删除

- 通过任务应用创建，或在「任务管理」直接创建：填写任务名称、执行智能体、提示词及可选结果输出要求。
- 保存后任务持续存在。完成一次执行不会消耗或删除任务；包括指定时间只执行一次的任务，也可再点击「立即运行」。
- 每条任务右侧直接提供「编辑」「立即运行」「删除」。编辑在独立弹窗修改名称、提示词、输入参数（应用任务）和执行计划，保存后回到列表，仍是同一个任务、不另建副本。点击任务名称在独立弹窗查看历史和报告，不在列表页展开详情。旧运行记录继续保存原参数和输出快照。
- 查看执行对话可处理审批；每次运行独立保存结果与失败原因，可查看报告、结构化数据及本次输入。
- 列表的「删除」需确认，删除后停止后续定时计划，历史运行记录、报告、json-result 和文件保留。当前正在运行时，等待完成再删除。删除不提供界面撤销，请确认名称。
- 「任务运行记录」集中查看历史，可搜索、筛选状态、分页及下载 `json-result.json`。结果输出位置当前为任务运行记录，不提供任意外部路径。

网络失败重试沿用当前提交编号，不重复执行；主动再次运行使用新的编号。参数和计划编辑不覆盖历史成果。

点击「立即运行」会打开深色任务监控窗，显示真实排队、执行、审批、失败或完成状态，以及耗时、执行阶段、工具活动摘要和可用Token用量。没有精确进度时不显示百分比；没有运行记录时只显示等待确认。网络中断不等于任务失败，监控会重新读取记录。关闭监控不会取消任务；运行中可从列表点击「查看监控」再打开。审批进入原执行对话，完成后可查看报告。日志仅显示当前关联运行的最近120条摘要，执行输出最多显示最近12,000字符，不展示模型思考链或原始工具参数。

### 11.3 执行时间与运行边界

点击「任务运行记录」中的任意记录，打开与立即运行相同的监控窗口。上方可切换「执行日志」「结果报告」「result-json」；下方也有查看结果和JSON快捷入口。报告与完整JSON均固定为所选运行，包含该次输入、状态、结果及错误信息，不会跳到最新一次运行。JSON可下载为 `json-result.json`。运行尚未完成、没有报告或读取失败时会明确提示，失败可重新读取；旧日志不可用不影响读取已保存的报告和JSON。

任务支持手动、指定时间一次、固定分钟间隔、每天、每周（可多选）或每月。日历计划默认当前设备时区，可修改；当月没有指定日期时按最后一天执行。计划可以暂停或启用，暂停不取消已开始的运行，手动运行不改变计划。

调度由服务端每约15秒检查，不依赖页面保持打开。退出应用、服务停止或设备休眠时不执行；恢复后只处理一个到期时点，不积压重放全部错过的周期。同一任务不重叠执行，失败不自动重试。需要审批时进入执行对话，结果仍回写原任务。

旧任务无需迁移，仍可编辑、运行、删除及查看历史；旧的模板创建接口已停用，不再接受新建请求。应用内部继续保留发布版本、参数校验和历史快照，用户无需操作模板。

## 十二、项目 {#projects}

项目是持续对话的工作空间，集中保存多轮工作的最终成果；需要多人协作时可以显式调用工作流。

### 12.1 创建项目

1. 打开左侧「项目」。
2. 点击「创建项目」，填写名称；项目说明可选。
3. 保存位置默认「系统自动创建」，无需设置；也可「自选保存位置」，桌面端点击「选择文件夹」。系统在所选位置新建独立项目子目录，不修改原有文件。浏览器端填写 API 服务所在电脑上已存在、可写的绝对目录路径（不是手机/浏览器设备的目录）。目录创建失败会提示原因并保留输入。项目默认仅自己可见，创建不会调用模型、规划 DAG 或自动执行；已有项目的目录不变。
4. 进入后发送消息或上传材料开始工作，默认通用助理，可在输入框切换员工。

### 12.2 确认与执行

1. 每次发送启动一轮独立执行，保留近期对话和已有文件，支持继续提问与修改。
2. 只有成功后才更新固定成果目录；失败或取消不会覆盖已有成果。运行中可停止。
3. 在文件树查看、编辑或预览成果。需要多员工协作时点击「调用工作流」；工作流独立执行，不自动改写来源项目。
4. 旧 DAG 项目仍保留原来的依赖图、增量调度与恢复入口，不自动迁移。数据应用沿用数据工作台的发布功能。

持续对话项目由输入框中选中的员工直接处理，不额外调用规划器或协调员模型。运行时显示简洁状态；失败原因显示在对应回答旁，已有结构化错误可展开「运行诊断」。系统提示统一标为「系统」，不再显示重复的调度提示和协调员汇总；审批、执行过程与成果附件仍保留。

### 12.3 复用资产

- 把资产库中的文件「链接到项目」即可纳入项目交付目录。
- 项目文件支持在浏览器中打开预览或一键定位到本机目录。

### 12.4 预览与发布应用

持续对话项目顶部提供「预览与发布」。生成根目录 `index.html`（兼容 `output/index.html`）后，可在弹窗预览页面及相对路径引用的样式、脚本、图片和字体。预览不代表业务功能已验收，请先操作页面检查效果。

- 展开「发布范围与资源清单」可核对文件。上传材料目录、隐藏配置、工具脚本不参与发布；不要在页面或 JSON 资源中保存密钥。
- 点击「发布应用」并「确认发布」，保存独立本地静态快照。后续对话或编辑只改项目成果，不自动影响发布版。
- 要更新时，重新预览并「更新发布」。文件或发布版本变化会提示重新预览；保存失败保留原版本。「打开已发布版本」仍可查看上次成功内容，即使本轮失败或网站入口被删除。
- 只读成员可预览，不能发布；执行期间不能发布最新成果，但可打开旧版。查看链接30分钟或 API 重启后失效，回到项目重新打开即可，已发布快照本身不会因此失效。
- 这里不部署到公网，不启动服务端程序；隔离预览限制外部资源加载、fetch/WebSocket 联网及 Workmate 管理接口/存储访问。普通超链接属于浏览器导航，不是完整网络沙箱；请只预览可信成果。需要数据库 CRUD 的应用仍使用数据工作台发布。静态资源上限500个、合计32MB、单文件8MB。

### 项目续聊与输入

普通项目每轮完成后保持可继续对话，默认使用当前员工，可切换或输入 @ 选择。每轮独立执行，不重跑前轮，也不自动规划下游。旧 DAG 项目仍仅目标员工及其下游按依赖增量执行，顶部「再次调度」代表完整新一轮。

普通项目失败或取消后直接发送新消息重试或调整要求，历史与已有成果保留。旧 DAG 项目的「恢复执行」只继续未完成步骤，「再次调度」把旧对话归档到历史运行。

项目输入支持 Enter 发送、Shift+Enter 换行、文档选择/拖放/粘贴文件和语音转文字。文档最多 10 个、合计 50 MB，上传失败需重试或移除后才能发送；语音识别后填入输入框，由你确认发送。发送失败保留草稿与文档；执行中可点击「停止执行」。新普通项目支持材料上传，隔离数据应用项目及旧本地项目暂不支持。沿用员工现有模型、技能及权限，本期不提供项目实时全双工语音或图片视觉输入。

### 项目共享

项目列表卡片上的「共享 · 当前范围」打开共享弹窗，可选择仅自己、组织共享或指定用户，并为指定用户设置只读/可编辑权限。点击保存后生效；取消或按 Escape 不保存。保存失败会保留选项并显示原因。项目编辑页不展示共享入口。对话上方的「项目说明」默认收起，点击可展开查看完整要求；长说明在限定高度内滚动，不挤占后续对话，智能体使用的要求保持不变。

任务模板的参数 UI 项目顶部提供「预览并测试数据」：直接预览最新成果，使用当前用户权限查询技能列表和已登记数据接口；用户身份不会传入页面。测试提交只校验并展示参数，不保存模板、不创建任务，也不需要发布静态应用。项目运行期间不能刷新测试预览。返回任务模板时自动同步最新有效界面到草稿；完成其余配置后，在最后一步验证并明确发布即可。普通项目的「预览与发布」继续使用隔离静态预览，不开放真实数据接口。

### 12.5 工作流

- **创建工作流**：左侧打开「工作流」，描述协作目标与期望交付，选择可参与的员工和规划模型。系统复用项目协调员规划员工步骤与依赖，确认页可查看流程图，并修改目标、员工、前置步骤及验收要求。名称留空自动取目标前 24 字。
- 规划可能产生模型调用费用，但不会执行员工任务或创建项目。没有配置模型时可以选择「手动编排」。返回修改目标会保留当前步骤，重新规划前需确认替换；保存工作流不会自动运行。
- 默认手动添加的新步骤依赖上一步，也可以取消依赖以并行执行；循环依赖不能保存。步骤无依赖时可独立开始，有依赖的步骤会等待上游结果。
- 点击「运行」，填写本次补充要求并点击「确认并运行」。系统创建独立 DAG 项目并进入原项目执行页，继续使用现有模型、审批、状态、工作区与交付机制。同一次请求重试不会重复创建项目，修改流程定义不影响已创建项目；本期尚不支持从普通对话自动选择工作流。
- **从普通对话调用**：输入框底部工具栏、「添加协作者」旁点击「调用工作流」，搜索并选择已保存的工作流，填写本次要求、添加参考文档后确认运行。沿用各员工自己的模型、技能与审批，可能产生模型调用费用，不使用对话框当前的模型覆盖。每次调用建立独立项目；进度、结果节选和成果卡片留在当前对话，重开仍可查看。从对话卡片打开执行详情后，可点击左上角「返回对话工作台」回到原对话。
- **从项目调用**：在项目输入框底部工具栏点击「调用工作流」，填写要求、选择本次参考文档后运行。每次创建独立执行项目，不修改来源项目的任务图、目录或文件；来源项目显示你发起的调用进度与成果。打开详情后，左上角「返回来源项目」可回到原项目，返回不会重新执行。项目正在运行或只有只读权限时不可发起新调用；旧本地项目不提供此入口。
- **材料与共享边界**：项目调用不会自动带上来源项目材料，也不会自动继承其共享权限。请在弹窗中显式添加所需文档；执行项目默认仅调用人可见，如需共享成果，请单独设置执行项目的共享范围。来源项目的其他成员不会看到你的私有调用记录。
- 工作流运行时可继续普通对话。卡片提供停止、恢复未完成步骤，以及「查看详情 / 继续协作」进入原执行项目进行审批、查看全文或修改成果。查看/下载已登记文件时复用资产归档，网站入口按完整 SITE 归档；失败会提示，可在执行项目中查看原文件。上传或启动失败保留本次要求；重试复用原调用，不重复开跑。首次提交后要求锁定，需要改要求请关闭后发起新调用。
- **基于成果提问**：普通对话中的工作流结束后，点击卡片「基于成果提问」，再在输入框提问。使用当前对话模型，只解释该次运行已保存的文本及文件清单，不读取文件正文，不修改文件或重跑流程；可能产生模型调用费用。引用可连续使用，点击「取消引用」恢复普通对话，切换或清空对话也会清除。问答模式不混用附件、协作者或自动调度。失败/取消的输出标为部分成果；没有真实文本时不提供推测答案。成果更新、被删除或权限变化时，请重新选择。答案保存在当前对话，按本对话共享范围可见；撤销执行项目权限不会删除已保存的对话历史。需要修改成果请进入原执行项目继续协作，项目内仍沿用增量任务逻辑。
- **参考文档**：运行窗口可添加 PDF、DOCX、PPTX/PPSX、Excel、CSV、Markdown、TXT、HTML，最多 10 个、合计 50 MB，单文件大小沿用附件限制。可只上传材料、不填写文字；上传解析失败可重试或移除。准备项目后材料锁定，原件与提取文本保留在项目 `inputs/`，所有步骤都能按路径读取，运行记录也会列出材料。提取文本为节选，扫描 PDF 不保证自动识别；需要完整内容时由员工通过已授权技能读取原件。
- **材料不足**：例如工作报告不含营收台账，员工应说明缺少的数据、提供有依据的分析框架并请求补充，不应搜索本机其它目录找替代数据。Pi 对话、项目及工作流的原生文件工具统一按工作区授权访问，AgentScope 宿主桥接复用同一规则，不再仅对带材料的任务生效。用户上传文件通过托管路径/附件工具读取；可信宿主单独登记的外部输入只授权读取该文件，不授权父目录或写入。Skill 资源仍通过已授权技能工具访问。Shell 检查不是完整操作系统沙箱；DSH 原生工具尚未接入宿主逐调用检查。达到步骤上限后停止执行，不建议靠提高上限解决重复探查。
- **运行记录**：展开工作流卡片中的「运行记录」，查看每次要求、实时状态、步骤进度、累计耗时、调度轮数、失败原因和已登记成果。审批操作仍在项目详情中进行；旧的未关联项目不会按名称猜测归入历史。
- **恢复运行**：失败或取消后，工作流记录中可点击「恢复未完成步骤」，项目顶部可点击「恢复执行」，保留成功步骤及成果，只继续未完成部分。失败尝试留下的文件会标为需核验，不代表成功交付；执行完成但没有文件时会明确提示，文字结果在项目详情查看。已完成项目的「再次调度」会开启完整的新一轮。已删除的项目不能恢复。
- **算法暂缓**：算法菜单暂不显示，已有目录代码与登记数据保留；本次不新增算法功能。员工原有 Skill 授权不受影响。
- 删除工作流或算法只移除当前用户的登记，不删除历史项目、底层 Skill 或员工已有授权。工作流和算法定义私有保存，不跨用户共享。

## 十三、远程办公 {#remote}

通过通道网关，你可以让外部 IM 或远程终端调度你的数字员工。

### 13.1 配置通道

1. 打开左侧「远程办公」。
2. 选择要接入的通道：
   - **Telegram**：填入 Bot Token，配置个人白名单。
   - **飞书**：填入 App ID / App Secret，配置白名单。
3. 保存后点击「重启网关」使配置生效。

### 13.2 使用方式

- 白名单内的账号可以直接在 IM 中向员工下达任务，消息会经由网关进入本地工作台执行并回传结果。
- 远程中继终端可通过出连（WebSocket）方式注册，供远端调度同一批员工。
- 网关状态、运行状态与默认员工可在页面中查看和调整。

### 13.3 安全建议

- 白名单务必只添加可信账号。
- 密钥保存在系统安全存储中，不会明文出现在配置文件里。

## 十四、环境检查与 dsh {#env-check}

Workmate 启动时会自动体检本地环境，缺少组件会弹出提示，你可以在「环境检查」页面查看每一项的「要求 vs 当前」并一键修复。

![环境检查与 dsh 章节](images/user-manual-5-env-check.png)

### 14.1 常见检查项

- 运行目录与数据目录可写
- Python 环境（Agent 脚本执行）
- AgentScope Sidecar（可选执行引擎）
- **dsh 编码 Harness**（DeepSeek 编码侧车，约 200MB）
- Docker（如需容器化）

### 14.2 修复流程

1. 打开「环境检查」页面（启动弹窗中点击「查看详情」，或从设置进入）。
2. 查看标红（需处理）/ 标黄（建议）的检查项，展开看修复说明。
3. 点击「一键修复」自动修复白名单项；其余项复制页面给出的主机 / Docker 脚本手动执行。
4. 修复后点击「重新检查」确认全部通过。

### 14.3 安装 dsh

- 首次检测到缺少 dsh 时会弹出安装引导（约 200MB 下载），点击确认后显示实时进度。
- 也可以手动在「环境检查」页面或设置中的 dsh 卡片触发安装 / 重装。
- dsh 未安装时，相关预置员工会自动降级为 pi 引擎运行，不会阻塞其他功能。

## 十五、设置 {#settings}

「设置」集中管理外观、模型、搜索、知识库、账号、用量、环境与通用运行参数。

### 15.1 标签页速览

| 标签页 | 内容 |
| --- | --- |
| 外观 | 主题（亮/暗/午夜/极光/跟随系统）、语言（简体中文 / English） |
| Provider | 模型服务商：新增、编辑、测试连通、删除 |
| 模型 | 对话模型与应用模型：添加、测试、查看健康状态、绑定默认能力 |
| 决策守卫 | 决策模型、开关、观察/强制模式、超时、失败策略和 Tool 前置安检 |
| 搜索 | 联网搜索服务商与端点配置 |
| 知识库 | 知识库服务商、默认配置及智能体经验的固定知识库目标与可用性验证 |
| Provider 与模型 · 实时语音 | 实时对话、独立 ASR、默认语音入口、工作桥、音色和兼容设置 |
| 账号 | 修改密码、会话安全设置 |
| 用户 | 本地用户管理（仅管理员） |
| 用量 | 主模型与应用模型按实际 Provider、模型和能力分别统计 |
| 环境 | 默认数字员工、环境检查入口、dsh 管理 |
| 通用 | 执行引擎（pi / agentscope / dsh）、Sidecar 池大小、共享运行数上限、运行时状态 |

### 15.2 常用操作

- **切换主题/语言**：在「外观」中选择，实时生效。
- **指定默认员工**：在「环境」中选择默认数字员工，新建对话时优先使用。
- **调整执行引擎**：在「通用」中选择默认引擎（进程内 pi / Python Sidecar / dsh），并可在运行时状态面板查看实时状态。
- **增强 PPTX 解析**：基础安装已能轻量读取幻灯片正文和备注。管理员可在「通用 → PPTX 增强解析」按需安装组件；安装后上传 PPTX/PPSX 时自动启用，异常时自动回退轻量解析。组件只保存在用户数据目录，可随时移除，安装过程需要联网。
- **增强 PDF / Word 解析**：基础安装使用轻量解析读取常用 PDF 和 DOCX。复杂版式、表格或阅读顺序要求较高时，管理员可在「通用 → PDF / Word 增强解析」安装 MarkItDown 与 Docling；系统仅在基础结果为空或质量较低时自动回退使用。增强组件及其原生依赖保存在用户数据目录，不增加基础安装包体积，可随时移除。
- **打开账户与配置**：侧栏左下角默认只显示一行紧凑入口，点击后可查看账号与组织信息、切换外观、进入设置或退出登录；它不会长期占用“最近对话”空间。
- **启用决策守卫**：先在“模型”中准备决策应用模型，再到“决策守卫”选择模型和运行模式。网络不稳定或所在地区可能无法访问时建议保持关闭，或使用“观察 + 自动放行”。

### 15.3 智能体经验设置 {#experience-settings}

管理员打开「设置 → 知识库 → 智能体经验 · 本地优先」：

1. 勾选「启用经验保存与加载」。默认可仅使用本地，不要求先配置 Embedding 或远端知识库。
2. 可选择一个固定系统经验知识库，当前支持已启用的 LanceDB / 百炼，建议使用专用库，只同步可共享经验。
3. 仅点击「保存设置」不会启用知识库调用；需要后台同步时点击「保存并验证知识库」，成功后显示“知识库可用 · 后台同步”。修改配置或关联配置指纹变化后须重新验证。
4. 未指定、验证失败或不可用时直接仅本地，不在每轮运行中等待超时探测。连接验证只证明检索可用，不保证写入权限或经验正确性；后台同步失败不影响本地经验保存。

知识库同步与语义预取使用有界后台队列，不自动补发全部历史经验；JSON 副本也是异步有界写入。配置关闭不等于删除已保存经验或知识库文档。经验与会话滚动记忆、可信查询资产是独立机制，分别承担方法复用、同会话连续性和明确收藏查询的职责。

## 十六、工程测试控制台 {#quality-console}

源码开发或发布验收时，可在仓库根目录运行：

```bash
pnpm quality:console
```

浏览器会打开 `http://127.0.0.1:47840`。控制台提供快速、实时语音、核心编排、完整仓库回归，以及并发和持续任务专项；可查看状态、实时日志和 JSON 报告。并发专项默认只预览，必须显式勾选“执行真实测试”才访问本地 Workmate API。控制台仅监听本机并只执行预置白名单命令。

停止控制台：

```bash
pnpm quality:console:stop
```

## 十七、常见问题 {#faq}

![常见问题章节](images/user-manual-6-faq.png)

**Q1：启动时提示「AI 模型还没有准备好」，怎么办？**
点击弹窗中的「去配置」直达设置页，按 [模型配置](#model-config) 章节补齐 Provider 与模型；也可以点击「以后再说」，应用会安静 7 天再提醒。

**Q2：对话一直停在「等待审批」，任务不往下走？**
这是工具审批机制在保护你。查看请求参数后选择允许或拒绝即可继续（见 [工具审批](#chat)）。

**Q3：环境检查报错，如何快速定位？**
打开「环境检查」页面，看标红项展开的修复说明；优先使用「一键修复」，其余按脚本手动执行。

**Q4：数字员工没有反应或报「model missing」？**
说明当前运行的默认模型不可用。到「设置 → 模型」确认默认对话模型已设置且可用。

**Q5：dsh 相关员工无法使用？**
先在「环境检查」中安装 dsh（约 200MB），安装完成后重启相关对话；未安装期间相关员工会以 pi 引擎运行。

**Q6：资产/项目文件想保存到本地？**
在「资产库」选中资产点击导出，或在「项目」文件树中定位到本机目录。

**Q7：如何让外部 IM 也能调用员工？**
到「远程办公」配置 Telegram / 飞书凭证与白名单，重启网关即可（见 [远程办公](#remote)）。

**Q8：配置了在线搜索但没生效？**
检查「设置 → 搜索」中的服务商端点与密钥是否配置并保存，并在对话发送前勾选「联网搜索」。

**Q9：模型测试窗口为什么不能点击外部关闭？**
这是为了避免长时间生图、语音或视觉测试被误触中断。测试执行期间关闭按钮也会禁用；成功或失败后可从固定的底部操作区关闭或重新测试。

**Q10：生成的图片或音频为什么没有预览？**
先确认执行过程已经成功提交资产。媒体卡片会通过当前登录会话加载受保护内容；如果鉴权过期或文件类型无法识别，会回退为普通文件卡片，可尝试重新登录或从资产库下载检查。

**Q11：生图时间很长，或者第一次失败后又成功，正常吗？**
异步生图通常需要轮询上游任务，耗时会高于普通对话；网络断开、内容安全拒绝或 Provider 临时不可用也可能触发可解释的失败。执行过程会保留请求阶段和错误原因，不会把失败步骤误报为已完成。

**Q12：启用决策模型后网络不可用，会不会影响所有任务？**
默认不会。决策守卫缺省关闭；启用时默认超时较短并采用“自动放行”，失败后还会短时熔断，避免持续拖慢主流程。只有主动选择“拒绝执行”失败策略时，决策服务不可用才会阻止工具执行。

**Q13：项目失败了，如何区分是模型还是网络问题？**

可在成员任务详情的「运行诊断」查看错误分类、发生阶段和等待时长。限流、认证失败、模型单轮无响应与连接中断分别提示，不再一律判定为本机网络问题。项目显示“执行未完成”时，已有文件仍保留；请按提示修正后再重试。旧运行不会自动补出当时未记录的诊断信息。

**Q14：模板没有定制参数界面和报告，为什么不能发布？**

智能体任务模板无需强制定制参数 UI 或 Schema，报告默认可用。先完成名称、执行智能体与提示词，在最后一步「配置验证」通过后发布。定制表单或固定 Skill 才需对应参数验证；失败时按字段提示修改，或返回执行配置检查是否选错 Skill。

**Q15：数据应用预览提示通道不可用或权限不足？**

从关联应用的项目「预览与发布」打开最新预览，确认当前账号已登录；无需先发布。普通静态网页没有数据通道，旧预览需关闭后重新打开。检查对象连接密码、数据库连通性、应用操作是否登记；写入还需对象写入及 SQL 审核。不要把密码放进网页，也不要关闭服务端鉴权来解决通道问题。

**Q16：保存经验会等待知识库或大量文件写入吗？**

不会等待 JSON 副本或知识库同步，只等待本地数据库持久化；副本写入和知识库调用在后台有界执行。知识库未配置或未验证可用时不调用，首次加载可能只有本地文本结果。SQLite 本身遇到慢磁盘仍可能耗时，不承诺所有存储操作零等待。
