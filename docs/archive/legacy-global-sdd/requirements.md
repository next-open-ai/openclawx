# OpenClawX 需求规格（历史总规格）

> 状态：历史参考。当前项目需求见 [项目需求总览](../../product/requirements-overview.md)，新功能进入 [功能 SDD](../../sdd/README.md)。

## 1. 产品定位与边界

OpenClawX 是本地优先的数字员工工作台，而不是单一聊天工具或纯 AI IDE。用户在对话、项目、自动化与编辑工作区中调用具备受控能力的数字员工；模型、Skills、工具执行、文件产物和权限均可追溯。

首要原则：**能力按需加载、执行有边界、产物可追溯、用户对高影响行为保持控制。**

## 2. 核心需求

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| CORE-01 | 提供独立 Vue 界面、Electron 本地运行时与 Fastify Agent API。 | 开发与生产包均能启动并完成一次健康检查。 |
| CORE-02 | 用户可配置多个 Provider 与对话模型，并在对话/任务处选择可用模型。 | 未配置模型时明确提示；已配置模型可被会话、自动化、项目任务复用。 |
| CORE-03 | 数字员工是职责与授权的载体。 | 员工目录仅显示职责；详情才管理可用 Skill 和默认候选 Skill。 |
| CORE-04 | Skill 采用渐进加载：先提供元信息，再按需加载 `SKILL.md`、资源与可执行入口。 | 未授权 Skill 不进入运行时；授权 Skill 不必将全部内容注入每轮上下文。 |
| CORE-05 | 支持工作区读写、受控脚本、依赖安装与网络访问。 | 每项能力受 Skill 执行策略与权限档位共同限制；危险删除始终不在“完全权限”内。 |
| CORE-06 | 生成的可交付文件自动归档到资产库。 | 资产携带运行、员工、会话/项目来源；可下载或在 Finder 中显示。 |
| CORE-07 | 支持单次与日/周/月自动化，并保存运行记录。 | 应用运行期间按计划触发；失败和产物可回溯。 |
| CORE-08 | 普通对话支持用户明确指定协作者。 | 协作者在隔离、只读上下文中并发提供摘要；主员工整合后统一答复，完整协作过程可展开查看。 |

## 3. 项目级多智能体编排（第一期）

### 用户故事

作为用户，我希望把一个目标提交为项目，由协调员把它拆为多个独立任务。我必须先审阅并确认草案；确认后，不同员工可并发完成各自任务，协调员只依据结构化子任务结果生成汇总交付，所有任务产物进入资产库。

### 功能需求

| 编号 | 需求 | 第一期开销控制 / 验收条件 |
| --- | --- | --- |
| PRJ-01 | 创建项目，记录项目名称、目标、协调员模型。 | 目标为必填；名称可由目标自动生成。 |
| PRJ-02 | 从瀑布、并发、讨论、DAG 模板创建草案，协调员可依据目标改写任务。 | 草案只生成，不执行；模型不可用或返回非结构化内容时保留保守模板草案。 |
| PRJ-03 | 用户可在确认前编辑任务标题、目标、员工。 | 未确认项目状态为 `draft`，不得触发任务运行。 |
| PRJ-04 | 每个任务独立配置员工、模型、Skill 和四档权限。 | 执行时只加载该员工已授权且被任务选中的 Skill；权限取任务档位。 |
| PRJ-05 | 按项目模式调度任务，彼此不共享会话状态。 | 并发任务可同时运行；瀑布与讨论/DAG 后续节点在前置节点完成后运行；每个任务拥有独立 Agent 请求、运行记录、工具过程和错误；不改变用户当前聊天。 |
| PRJ-06 | 子任务完成后由汇总任务读取结构化结果。 | 汇总提示只含项目目标和成功子任务结果；不得虚构失败任务信息。 |
| PRJ-07 | 失败可重试，运行中可取消尚未开始的任务。 | 已开始外部操作不会被强杀；取消会阻止队列中任务并留下记录。 |
| PRJ-08 | 项目、任务、任务运行与汇总结果可持久化。 | 重启后可查看状态、结果、失败原因与资产。 |

### 非目标（第一期）

- 不支持条件分支、循环、子项目或员工之间无限制互聊；DAG 仅支持模板/草案中的显式无环前置关系。
- 不自动执行高风险外部动作；不绕过已有审批策略。
- 不提供云端后台调度；项目执行要求 OpenClawX 桌面应用与本地服务处于运行状态。

## 4. 权限模型

| 档位 | 默认行为 |
| --- | --- |
| 只读 | 可读取授权 Skill 与工作区；禁止写入和脚本执行。 |
| 默认工作权限 | 按已授权 Skill 的策略允许工作区写入、脚本运行和依赖安装；其他能力申请批准。 |
| 扩展权限 | 在默认基础上减少非危险能力的逐次阻塞，仍遵守 Skill 限制与网络白名单。 |
| 完全权限（非危险） | 放行已定义的非破坏性能力；删除、覆盖不明目标、凭据暴露和特权操作仍需独立保护。 |
