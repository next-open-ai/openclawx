# 测试规格

> 状态：实施中｜规格版本：0.1｜更新日期：2026-09-23

| ID | 场景 | 预期 |
| --- | --- | --- |
| ONT-TEST-01 | 写入后重新读取图谱 | 节点、关系和版本保持一致 |
| ONT-TEST-02 | 用别名查询实体 | 返回标准实体及扩展词 |
| ONT-TEST-03 | 查询有一跳关系的实体 | 返回关联节点和关系 |
| ONT-TEST-04 | 图谱为空或无匹配 | 策略为 `vector-only`，原向量检索正常 |
| ONT-TEST-05 | 图谱匹配且关联文档 | 原始与增强路径合并去重，提示文档合理加权 |
| ONT-TEST-06 | 首次打开含旧 JSON 的知识库 | 自动生成 `ontology.sqlite`，图谱、候选和审核状态保持一致，旧文件不删除 |
| ONT-TEST-07 | 发布及候选提交 | 节点、关系、候选状态与版本快照在同一事务中提交 |
| ONT-TEST-06 | archived 节点或关系 | 不进入查询计划 |
| ONT-TEST-07 | 非法 API 输入 | 返回 400 和契约错误，不写入文件 |
| ONT-TEST-08 | 无权限/过期/错误版本候选 | 在进入模型上下文前被硬过滤（P2） |
| ONT-TEST-09 | 模型返回实体与关系 JSON | 转换为符合契约的候选，证据中的 documentId/chunkId 必须来自本次选定切片 |
| ONT-TEST-10 | 模型返回代码围栏、额外文字或非法引用 | 可提取合法 JSON；非法候选被拒绝且不写入审核队列 |
| ONT-TEST-11 | 用户发起文档分析 | 生成候选后仍为 pending，只有人工接受并提交后才进入正式图谱 |
| ONT-TEST-12 | 13 个短切片发起自动识别 | 按 4/4/4/1 分批，不截断任一源切片，最终候选合并后一次写入审核队列 |
| ONT-TEST-13 | 某批模型 JSON 被截断或格式错误 | 自动二分该批并重试；单切片仍失败时返回可理解的错误，不暴露底层 JSON 位置异常 |
| ONT-TEST-14 | 单个内容密集切片仍生成不完整 JSON | 仅在分析上下文中按自然边界继续缩小，候选证据仍引用原始 chunkId，知识库切片不被改写 |
| ONT-TEST-15 | 同一批包含可信证据和模型改写/编造的证据 | 丢弃证据不可核验的节点及依赖关系，可信节点继续进入人工审核区 |
| ONT-TEST-16 | 在本体检索验证区输入命中别名的问题 | 显示 `ontology-enhanced`、命中实体、关联节点、关系、扩展词和融合后的知识片段 |
| ONT-TEST-17 | 输入未命中正式本体的问题 | 显示普通向量召回及退化说明，原始向量结果仍可用 |
| ONT-TEST-18 | 正式本体为空、包含实体关系或超过 300 个实体 | 分别显示空态、可交互关系图或范围提示；搜索、布局切换、缩放和详情查看可用，候选数据不进入正式图谱视图 |
| ONT-TEST-19 | 至少 3 个顶层批次发起自动识别 | 同时运行的顶层批次不超过 2；即使后发批次先完成，最终候选仍按原批次顺序合并；失败批次继续使用既有缩小范围重试。 |
| ONT-TEST-20 | 在正式本体关系图进入和退出全屏 | 全屏中搜索、布局、缩放和详情可用，画布填满可用区域；按钮和 Esc 均可退出，退出后恢复嵌入布局。 |
| ONT-TEST-21 | 用实体别名和关系词执行两跳查询 | 查询计划返回逐跳路径、涉及实体和关系、扩展词及绑定的 documentId/chunkId，最大深度不超过 2。 |
| ONT-TEST-22 | 使用实体类型、关系、属性或方向约束查询 | 只遍历满足受控约束的正式节点和关系，archived 数据不进入结果。 |
| ONT-TEST-23 | 图谱实体或关系绑定知识切片 | 最终结果融合原始向量、本体扩展向量和图谱证据三条路径；证据读取失败时仍保留两条向量召回路径。 |
| ONT-TEST-31 | 普通成员尝试发布或回滚，管理员执行相同操作 | 普通成员收到 403；管理员成功，版本发布人等于认证账户而非客户端输入。 |
| ONT-TEST-32 | 分别在本体开启、关闭和图谱损坏时调用 `kb_search` | 开启时返回增强策略；关闭时仅执行普通检索；图谱异常时自动降级且仍返回可用向量结果。 |
| ONT-TEST-33 | 规则未命中时由应用模型返回合法、低置信度、越界 ID 或非法 JSON | 仅候选集合内且置信度不低于 0.72 的实体进入受控图遍历；其他结果不采用，原始检索继续可用。 |
| ONT-TEST-34 | 导入可提取文字的 PDF、DOCX、PPTX 后发起本体识别 | 文档先形成可追溯切片，候选证据引用真实 documentId/chunkId；未安装 PPTX 或 OCR 组件时返回明确能力提示。 |

## 当前自动验证

```bash
pnpm --filter @openclawx/contracts build
pnpm --filter @openclawx/agent-core typecheck
pnpm --filter @openclawx/api typecheck
pnpm --filter @openclawx/agent-core test
```

阶段验收还必须覆盖一次真实 Embedding 服务和 LanceDB 的端到端混合检索，不以纯单元测试代替。

- ONT-TEST-24：后台抽取任务返回任务 ID，页面刷新后可恢复查询状态并在完成后进入候选整理。
- ONT-TEST-25：候选增删改、暂缓和合并不会直接修改正式图谱，暂存后才形成待发布草稿。
- ONT-TEST-26：发布前返回变更摘要与分级校验；版本发布记录说明，回滚以新版本保存且不覆盖历史。
- ONT-TEST-27：规则扫描识别重复实体、命名问题、孤立节点、无效端点、自循环和重复关系，并准确区分阻断与建议。
- ONT-TEST-28：合并治理命令迁移关系、合并别名和属性并写入操作记录；撤销恢复操作前草稿。AI 输出只能通过治理命令契约。
