# MDA-1 · 受控数据应用首版

规格版本：1.5 · 更新日期：2026-10-13 · 关联：[数据能力架构](../../../architecture/data-capability-platform.md)

当前增量：[MDA-SQL · AI SQL 与统一预览](./sql-operations.md) 取代下方首版 R2 的仅结构化约束，以及首版只读/发布后才能数据验证的限制。旧结构化定义保留；新 SQL 操作经 AST 权限校验、实际只读测试登记，写操作须用户批准与对象写入开关。模型工具永不执行写入。

MDA-R12/T22 增量允许 MySQL 新业务表草稿：独立结构权限及管理员逐方案审核执行，成功后显式纳入对象与当前应用；并非普通查询/CRUD开放DDL，也不会自动扩大其他应用范围。详见上述增量规格与状态证据。

MDA-R13/T23 将按场景注入的数据能力说明与沙箱静态交付规范分开，项目背景不重复工具协议；普通员工与无数据工具运行不承受应用交付约束，不改写旧项目背景或放宽网关权限。

## Requirements

- MDA-R1：数据对象 → 只读应用 → 持续对话项目；默认使用对象内所有表，不要求选择单张主要表。授权范围是创建时对象内的表集合。新增加的表不自动授权。
- MDA-R2：AI 只可用结构化查询定义；网关编译参数化 SQL，实际成功查询后登记应用操作。查询参数只能替换已有筛选值/分页，不可替换表、字段、关系或 SQL。
- MDA-R3：运行身份及对象权限每次重新验证；页面发布 token 不是数据权限。敏感字段不可查询。越界拒绝并提示先调整对象、重新创建应用；首版不提供隐式扩大范围。
- MDA-R4：页面通过宿主 SDK 调用已登记操作；沙箱页面拿不到登录凭据。访问者必须登录且是应用所有者；共享执行暂不开放。
- MDA-R5：登记成功、页面绑定、业务验收是不同事实；绑定要求至少一个已验证操作。查询失败不覆盖上次有效定义。

## Contracts

### MDA-R10 / T10 · 编辑来源与运行草稿可见性（2026-10-12）

从数据工作台打开应用项目，保存账号/组织限定的临时返回来源及对象位置；返回原对象应用页，不返回项目列表，不串号。其他项目入口清理来源，嵌套工作流先返回来源项目。项目左侧区分正式成果与最新未成功轮次 output 内的只读草稿；草稿不可保存、发布或自动晋升，分片未完成不伪称存在文件。新认证 GET `/orch/projects/:projectId/runs/:runId/draft-files` 和 `/draft-file?relative=...`：服务端校验项目与 Run 所有权、session/task 关联，由 Run ID 推导 output 目录，不接受根目录；拒绝路径穿越/符号链接/隐藏目录，最多500文件、深度12、单文件2MB，仅文本代码查看，无写入接口。缺失目录为空，其他读取失败明确提示。兼容无迁移，回滚入口不删除草稿。测试覆盖跨用户/项目/Run、路径/符号链接、有草稿失败仍保留正式成果、刷新/切换防串文件、返回来源隔离；不访问实际用户库或调用模型。

`queryMode: managed-readonly` 是新建请求的可选增量字段；缺省仍保留旧客户端路径。新增 app query Zod 契约、运行上下文派生的应用工具、认证 POST 查询接口。持久化保存结构化定义/参数定义/验证时间/结果字段，不保存样例业务行、凭据或手写 SQL。运行时用最新 Schema 重新编译。

## Compatibility / rollback

### MDA-3 · 对象 Schema 优先、按需补充（2026-10-12）

- MDA-R8 / T8：默认 `data_get_schema` 仅读已保存对象 Schema，不访问数据库。应用先读 tables 目录，再取相关表列/关系；大对象不等于必须扫描全库。
- MDA-R9 / T9：结构说明不足时，显式 `origin:database` + tableId 补充当前实时对象内已绑定表的原生字段类型、可空性和数据库列说明。仅参数化定点元数据 SELECT，不扫描表目录或业务行，不修改对象 Schema、绑定或授权。对象业务标注优先，不覆盖；新表/新列仍需用户调整对象，不自动使用。快照对象不支持实时补查。
- 公共契约：origin 可选，缺省 object；database 必须有 tableId，不允许 view。结果标注 metadataOrigin、数据库补充字段及范围提示；敏感字段和查询返回前撤权检查仍生效。
- T8/T9 验证：本地 Schema 零远程请求，MySQL/PostgreSQL 定点查询参数与敏感过滤，未知表/无关连接拒绝、取消不返回、分页预算、对象标注不被覆盖。回滚移除 origin 扩展即可，无数据迁移；本轮不操作真实库。

### MDA-2 · 创建前检查与完整元数据（2026-10-12）

- MDA-R6 / T5：实时对象创建或重新执行应用前，检查所属连接凭据是否可用。缺失返回 409 / `DATABASE_CREDENTIAL_REQUIRED`，不创建项目或启动模型；提示在数据库连接中重新填写密码。桌面安全存储失败返回 503，不降级明文存储；空密码是有效已配置值。检查不声称真实数据库已连通。
- MDA-R7 / T6：`data_get_schema` 增量支持 tableId、view（tables/relations）、offset/limit。小 Schema 保持完整返回；大 Schema 返回有界目录，按 tableId 分页取列，关系可单独分页。每页有 hasMore/nextOffset；原始表范围、所有权及敏感列过滤不变。问数工具有独立的 16K 字符上下文预算，防止通用 2.5K 截断破坏协议。
- MDA-T7：创建弹窗显示全部表已纳入范围；名称默认对象名，内部 tableId 仅保留为历史存储锚点，不限制对象查询范围。
- 验证：T5 合成凭据缺失/恢复/空密码、无模型启动；T6 大 Schema 遍历/敏感过滤/上下文不截断；T7 创建弹窗与重试回归。无需改历史数据，无真实业务库操作。撤回入口及可选分页参数即可回滚，不回退数据权限。

新增独立表；不迁移历史应用或改变历史 token 数据接口。新模式始终禁止旧 CRUD 接口。回滚 UI 新模式入口可停止新建；不要删除范围表或让新模式退回旧 token 接口。旧客户端继续使用原行为。真实 MySQL/PostgreSQL、模型生成质量及完整业务口径需在配置环境验收。
