## 交付

- 员工运行设置中的“数据问数”：显式多选、搜索、刷新、空态、错误、失效关联提示、清空；本区域独立“保存数据关联”并反馈状态，默认关闭。关联接口同时支持普通成员与管理员，只写当前用户的专属KV键，不依赖浏览器localStorage／通用KV。Pi/AgentScope原生工具，DSH明确提示暂不支持。
- 可信runner绑定RunRecord，异步运行域隔离执行器；私有资源及有效所有者、用户命名空间关联每次重新核对。共享场景保守拒绝，无全局prefs回退，无模型身份授权。
- Gateway共享查询执行入口，原POST行为兼容；安全Schema投影、敏感列全部操作拒绝、取消/错误/容量限制、返回前复核撤销。自然语言解释由原智能体完成，不新增规划器或模型调用路径。
- JSON Schema从contracts的Zod生成，新增直接依赖 `zod-to-json-schema@3.25.2`（锁文件中原已有，离线安装，无下载）。API持有连接执行，模型没有数据库凭据。

- 单表只读，不含JOIN、全库问数、跨源、服务账号、完整行列级RBAC、独立审计持久化。默认不挂载，操作关联不会自动改变对象写权限。
- 私有运行按持久化所有者执行；共享场景禁用，不冒充当前调用者委托。没有新登录会话票据；账号有效性每次复核，已开始的SQL可能继续执行，但撤销后不向模型返回新结果。
- 查询内容会进入模型及现有运行/对话记录，撤销关联无法删除历史披露。业务说明可能含用户主动输入的敏感内容，请在关联前核对。通用shell、第三方MCP、外部数据工具不在本次网关授权边界中自动禁用，不宣称OS强沙箱。
- 默认执行器不向旧 `/api/chat` 无身份直调接口开放问数。纯text-only成果问答没有工具。DSH暂不支持，不强制改变员工引擎。

## 使用、兼容与回滚

重启API并刷新renderer（或重启开发态应用）后，数字员工→选员工→运行设置→数据问数→勾选→保存数据关联，再在私有对话/项目选择该员工提问。默认不关联，不迁移已有数据。清空关联并保存阻止后续工具调用；撤销runner接入和UI可回退，旧SDQ查询仍可用。规格及追踪见 [README](README.md)。
