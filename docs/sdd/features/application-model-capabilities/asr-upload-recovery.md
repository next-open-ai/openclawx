# AMC-ASR-NET-002 · 上传恢复与新轮次重试

状态：已实现，Mock回归通过。2026-09-29。

## 需求与契约

- R1：阿里临时文件上传遇到网络异常且未取消时，默认通道最多尝试两次，随后以 Node 原生 HTTP/TLS 兼容通道尝试一次；每次间隔500ms并使用新对象key，避免与禁止覆盖策略冲突。可能遗留临时对象，由厂商临时存储生命周期清理；不创建额外转写任务。
- R2：上传HTTP错误不自动重试；凭证、任务提交、查询分别标识失败阶段。任务提交不自动重放，避免重复计费。
- R3：ASR失败返回stage、attempts、retryScope=current_run、retryable=false、canRetryInNewRun=true；retryable仅限制当前运行，不代表永久不可用。新工具会话重置状态。
- R4：Pi当次系统指令明确运行边界：历史失败不阻止用户新一轮明确重试；不得将历史错误当作本轮已调用证据。
- R5：复用现有工具进度显示上传尝试、有限恢复及最终失败阶段；不输出凭证、签名查询串或音频内容。

## 任务与测试

NET-002-1：上传重试与阶段错误；NET-002-2：运行内结构化阻断与Pi指令；NET-002-3：回归与构建。

测试：首次reset后恢复、默认通道连续reset后兼容通道恢复、原生 multipart 请求可被真实本地 HTTP 服务接收、三次reset停止、对象key不同、HTTP403不重试、取消不重试、任务提交不重放、同运行阻断、新运行重新发请求、诊断脱敏。真实厂商网络根因和识别质量不以mock冒充验收。

## 兼容与回滚

保留retryable字段并补充作用域；不改配置/持久化schema。回滚上传重试到单次请求不影响现有绑定。历史AMC-ASR-NET-001中的“全部POST均不重放”由本增量限定：只有临时文件上传允许新key重传，推理提交仍不重放。
