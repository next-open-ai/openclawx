# 第一期：普通对话 / 项目双路线演示

执行 `pnpm routes:demo`。此演示通过实际 chat/project 服务入口、内存编排存储、确定性 runner 和临时项目目录运行，不调用真实模型、不生成真实业务应用、不写用户 Session 或资产库。

| 路线 | 入口 | 结束前可见 | 成功 / 失败检查 |
| --- | --- | --- | --- |
| 普通对话 | chat.createChatSession → sendUserMessage | 文本增量、工具过程，Run 仍为 running | 会话回复与 Run 一致；失败保留部分内容并提示未完成 |
| 专属项目 | projects.createDraft → confirmProject | 同一执行核心的文本/工具事件 | 项目和 Run 终态一致；模型无响应的阶段、180 秒特征被保留 |

每条路线各演示成功与失败一次，共四例。客户端回归执行真实 Vue setup：已有服务端摘要也要显示准确终态；已有实时 transcript 也要补齐最终诊断；重复刷新合并；工作区同步合并、短时缓存、失败可重试。

下一步人工真实验证（未执行）：

1. 普通对话提出一个简单文件任务，观察增量文本和过程；完成后下载交付物。
2. 数据工作台选中数据表创建应用，进入专属项目，观察执行过程、项目文件和实际发布页面绑定；再次优化应回到同一项目。
3. 使用测试模型制造限流/无响应，检查任务详情诊断，确认不显示虚假成功、不自动重放工具。

真实模型调用需确认模型、数据边界与费用。这里的隔离演示不能证明 GLM 或其他线上供应商已恢复正常，也不替代浏览器/桌面人工验收。
