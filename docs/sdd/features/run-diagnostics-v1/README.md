# 运行诊断与双路线演示

规格版本：1.1 · 更新：2026-10-11

- RD-R5/T5（余额不足）：共享模型诊断识别 HTTP 402、明确的 Insufficient Balance / InsufficientBalance / Arrearage / 余额不足错误，新增 `UPSTREAM_BALANCE` 分类。提示“模型服务账户余额不足或已欠费，本轮未完成。请到供应商控制台检查余额并充值，或切换其他供应商。”不自动充值、切换、重试或推断其他未知错误为欠费。兼容 SDK 丢失结构状态后以 `402 ...` 开头的文本；401/403/429/5xx 保持独立分类，普通额度/速率限制不直接当成欠费。
- RD-T5 验收：结构化状态、SDK 字符串、显式余额错误码/中英文文案、非余额反例与脱敏；真实 Pi SDK 连接本地模拟 402 服务，确认唯一失败、没有工具执行/成功事件；chat/project 的 RunRecord、终态事件及可见回复携带一致余额诊断。不调用真实供应商、不读取余额或修改现有运行。
- RD-R5 展示补充：项目即使已收到部分模型文本，余额不足终态仍必须追加到可见回复，不能被先前“正在处理”的文本遮盖。保留已有文本；仅本期余额分类改变此分支，不扩大其他失败类型的展示策略。

兼容补充：新增枚举值为同版本生产者/消费者一并部署，旧无 failure 的记录保持可读；无数据迁移，不补写历史原因。回滚时应同时回滚契约与分类器；含新枚举的历史记录保留，新契约仍可读取。影响模块：contracts、agent-core、orchestrator 测试；界面沿用现有服务端错误展示。

- RD-R1/T1：run.failed 可选 failure 结构（分类码、阶段、耗时、上游状态、传输码、规范化错误特征），传到 RunRecord 和 run.settled；旧事件兼容。区分模型无响应、上游限流/认证/服务错误、连接中断、工具参数错误、未知错误；不把所有错误归咎于用户网络。只存规范化证据，不存响应体、Prompt、凭据、URL 或任意原始错误文本。不自动重放工具，不增加超时。
- RD-R2/T2：项目失败/取消/待审批显示准确提示，不用“完成任务编排”冒充应用成功；任务展开显示服务端错误和诊断码/阶段/耗时。
- RD-R3/T3：同一项目刷新单飞；工作区同步同用户/root/run 合并、短时去重、有界缓存、失败可重试；运行中的 transcript 刷新不反复复制目录。文件树 watch 按标量变化触发，自动刷新不重复恢复。
- RD-R4/T4：隔离演示同一目标的 chat 和 project 服务入口，检查即时进度、失败诊断、各自消息/状态与 RunRecord 一致。确定性 runner，不调用真实模型、不触碰用户数据。真实模型演示需另行确认。

契约：contracts 新增可选 RunFailureSchema；旧事件/运行兼容，无数据库迁移。回滚调用方与可选诊断字段即可，不重写历史记录。

测试：分类/脱敏（伪造密钥/响应体）、旧/新事件、chat/project 两路线回归、同步去重/失败重试/用户隔离/期限、准确终态文案与项目回归；相关包 test/build/typecheck 和 concurrency:regression。状态另记，未执行不标为通过。
