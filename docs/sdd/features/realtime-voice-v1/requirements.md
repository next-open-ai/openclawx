# 实时语音 V1 需求

2026-10-14：桌面插话打断以 [BI-R5（1.2）](./barge-in.md) 为当前规格：普通插话交给供应商，明确停止播报走桥接，后台任务取消独立。

## 目标

在 Workmate 聊天页提供火山端到端全双工实时语音入口，实现持续收音、实时转写、流式回答、流式播音和用户打断基础闭环。

## 约束

- 火山 API Key 只存在于 Workmate API 服务端，不得返回或下发到浏览器。
- 管理员可在「设置 > 语音」保存 API Key、模型、音色、助手指令与主动开场开关；读取时只返回密钥掩码。
- 配置页提供 Dialog ID、系统音色、复刻音色、语速、音量、唱歌开关，以及复刻音色训练、导入和状态查询。
- 浏览器只能访问经过 Workmate 登录鉴权的 `/api/voice/realtime/*`。
- 每个语音会话绑定创建者的组织和用户，其他用户不可读写。
- V1 不开放 demo 本地文件工具；通过默认关闭的工作关联开关桥接 Workmate 员工任务，复用 Skill、MCP 和审批机制。
- 输入为浏览器采集的 16 kHz mono PCM s16le，输出为 24 kHz mono PCM s16le。
- 浏览器请求系统回声消除、降噪和自动增益；其实际效果由操作系统与浏览器实现决定。

## 验收

1. 聊天页可打开实时语音窗口并开始、静音、结束通话。
2. 前端源码和网络请求中不包含火山 API Key。
3. Workmate API 能直接连接火山 WebSocket、承载音频和 SSE 事件流，并隔离不同用户会话。
4. 语音服务未启动或未配置时显示明确错误，不影响普通聊天。
5. Workmate 类型检查、构建和火山真实握手验证通过。
6. 保存配置后可直接打开仿 SeedDuplex 的通话测试界面，验证真实鉴权和音频闭环。
7. Function Calling 不接受任意本地工具 JSON，只发布受控工作工具；重复 call_id 不重复启动任务，关闭开关后不再执行新工具调用。
8. Agent 完整输出默认留在当前前台对话，语音只获取短状态；无当前对话时新建可见会话。挂断不取消已接受工作，审批在关联对话完成。详见 VWB-05。
9. 配置支持实时对话 / 语音输入；独立 ASR 默认共用密钥，可单独配置；识别文字只在用户确认后追加聊天输入，不自动发送。详见 `asr-input.md` 的 ASR-01–04。
10. 实时对话默认按火山协议要求持续、等速上传音频，不以客户端活动门控改变分包节奏或重复提交已由服务端判停的回合；实验性节流代码保留但不得默认启用。
11. 收起字幕时只显示最新一句，不自动轮播、不提供前后翻页；点击“展开字幕”后显示本页完整语音记录。
12. 手动静音或持续约 5 秒数字静音时不得继续长期上传零值 PCM；应发送 `input_audio_mute.commit` 后暂停上传，恢复收音或检测到有效输入时先发送 `input_audio_unmute.commit`，且控制事件与音频上传必须串行。
# RV-18 — 实时语音传输与日志降噪

- 桌面端应以约 100ms PCM 批次上传实时语音，避免每 20ms 建立一次 HTTP 请求。
- 批处理不得显著增加用户可感知的语音首包延迟。
- 高频音频上传接口不记录逐请求访问日志；会话、错误和状态转换日志必须保留。
- 静音检测与 5 秒自动暂停上行逻辑保持不变。
