# 工作流与算法 · WA-V1

状态：第一阶段已实现并通过隔离验收。范围为 OpenClawX；不改变其他子项目，不替换现有项目调度器。

## 需求、契约与测试

- WA-R1 / WA-T1：增加工作流与算法导航；沿用现有主题与表单、空态、加载态、错误态。工作流定义与算法登记均通过登录用户作用域 API 持久化，普通成员不能访问他人定义。
- WA-R2 / WA-T2：工作流定义为名称、说明、员工节点（目标、依赖、交付要求）。最多 30 节点，ID 唯一、依赖存在、不自依赖、不成环；Zod 契约在 contracts。发布、嵌套、条件节点、参数 Schema、对话自动调用不属于本期。
- WA-R3 / WA-T3：运行时复制定义到新的普通 DAG 项目，使用既有项目固定工作区、授权、审批、RunEngine、成果与状态页面，不新增调度器。定义编辑不会改变已有项目；用户点击运行后进入现有项目执行页。运行前校验员工存在，不注入额外技能授权。
- WA-R4 / WA-T4：算法登记引用已安装非系统 Skill，不上传任意可执行代码；Skill 是算法实现及权限事实源。算法名称、用途与版本仅为目录信息，不替代 Skill 指令。员工关联复用现有 setPolicy，显式操作，不直接提升脚本/网络权限。取消算法登记不删除 Skill 或既有员工授权；页面说明此行为。
- WA-R5 / WA-T5：算法关联与运行可用性分开，显示“运行时验证”，不伪造测试成功。支持进入技能管理与员工关联；未知/删除 Skill 明确报错，不静默替换。

API：`/api/orch/definitions/{workflows|algorithms}` GET 返回 items；PUT `/:id` 接受对应定义并验证路径 ID；DELETE `/:id` 只删除当前用户登记。坏输入 400，其他用户条目不可见。每条记录独立键 `definitions:v1:<org>:<user>:<kind>:<uuid>`，api 单写者，无密钥。无旧数据迁移；回滚入口不会删除既有项目、技能或登记。

验证：Fastify 注入测试覆盖读写、更新、删除、用户隔离、非法依赖和环；Renderer 类型检查/构建；相关 API 与编排回归。真实模型运行不在自动验收中调用。
