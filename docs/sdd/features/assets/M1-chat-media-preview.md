# ASSET-M1 · 对话资产多媒体预览

状态：已实现，自动化工程验证通过，待桌面安装态视觉验收。

## 需求与范围

- ASSET-R1：对话中的已归档图片资产显示缩略图；点击缩略图可按既有资产权限打开原文件。
- ASSET-R2：音频资产在卡片中显示原生播放器，支持播放、暂停、拖动和音量控制；视频资产沿用同一机制显示内嵌播放器。资产内容接口支持单段 HTTP Range 请求，确保较大音视频可定位播放。
- ASSET-R3：下载、资产库、数据导入和站点清单等原有操作保持不变；非媒体文件继续显示现有文件卡片。
- ASSET-R4：媒体类型优先使用归档资产的 MIME，扩展名仅作兼容回退。使用既有受控资产内容地址，不生成 Base64、不复制媒体、不绕过资产鉴权。
- ASSET-R5：图片懒加载，音视频只预载元数据且不自动播放；加载失败时回退到普通资产卡片，不阻塞消息渲染。
- ASSET-R6：受保护媒体必须通过带会话凭据的请求加载，再以可撤销 Blob URL 交给原生媒体元素；禁止把会话令牌拼入资源 URL 或日志。

非目标：本阶段不生成视频海报帧、不做波形图、不改变资产存储格式，也不为 PDF/Office 文件增加新预览器。

## 设计与任务

1. ASSET-01：增加纯函数媒体分类，统一 MIME 与扩展名规则。
2. ASSET-02：新增独立 `ChatAssetMediaPreview` 组件，图片、音频、视频分别使用浏览器原生安全元素。
3. ASSET-03：资产卡片调整为“媒体预览 + 文件信息与操作”两层布局，保留全部既有按钮。
4. ASSET-04：增加分类回归、Renderer 类型检查和生产构建。
5. ASSET-05：补全归档 MIME 映射与媒体 Range 响应；旧会话镜像 KV 使用 8 MiB 有界请求体，媒体二进制始终不进入 KV。
6. ASSET-06：媒体组件使用鉴权 fetch 获取 Blob，资产切换、请求取消和组件卸载时释放 Object URL。

## 验收

- ASSET-T1：PNG/JPEG/WebP/GIF/AVIF/SVG 被识别为图片；MP3/WAV/M4A/AAC/FLAC/OGG/OPUS 为音频；MP4/WebM/MOV/M4V 为视频；普通文件和 bundle 不显示媒体预览。
- ASSET-T2：图片使用懒加载并可打开原文件；音视频无自动播放且只预载 metadata。
- ASSET-T3：媒体加载失败后卡片文件名、大小、下载和资产库入口仍可用。
