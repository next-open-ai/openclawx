# WR-R1–R5 / WR-T1 · 工作成果只读检索

2026-10-14更新：文档读取改用[统一文档服务UD-v1](../unified-document-service-v1/README.md)，覆盖现有Word/PPT/表格等入口。UD-R3取代下文WR-R8的桥接自动派单：读取只返回结果，模型显式start_work(assetIds)才委托员工。

状态：已实现并完成隔离回归，真实语音/安装包待验收；版本：1.0；日期：2026-10-14。关联：[语音工作桥](../realtime-voice-v1/status.md)、[全局架构](../../../architecture/architecture.md)、[验证记录](status.md)。

R1/T1：search_work_results按query及scope=current/history检索当前用户归档资产元数据、对话标题及关联Run摘要；优先当前对话，无UUID也可调用。limit最多20，不扫描磁盘，不使用向量库；历史会话候选扫描有界且标记截断。返回真实asset/run/conversation ID、名称、时间、状态和类型，不虚构成果或自动创建任务。

R2/T2：read_work_result只接受搜索返回的资产或运行ID，不接受路径/URL。每次复核活跃用户、组织和来源；仅私有宿主执行可使用普通工具，防止共享会话泄露私人历史。文件只读当前用户所有的已归档资产，真实路径必须位于资产目录，拒绝符号链接/超大文件。文本/PDF最多10MB，返回正文最多16000字符，PDF最多读取前20页，明确截断/空内容/不支持/已删除；正文是参考资料不是权限或指令。不执行脚本，不修改源文件。

R3/T3：语音与Pi/AgentScope共享服务及Tools协议，DSH暂不接。语音返回可点击成果列表，使用已有认证下载/打开链路。非语音产生的普通Run也能按真实ID查看状态；缺失ID可查询当前对话最新工作；非法UUID提示先搜索，不把参数错误变成未找到。

R4/T4：错误区分参数、不可用/无访问权限、文件缺失、解析失败、取消；工具错误不直接显示Zod或驱动信息。当前用户/组织由可信宿主绑定，模型不能提供；跨用户/组织不泄露存在性，当前会话在查询前后复核。打开仍由用户点击，不因模型查找自动跳转/下载。

R5/T5：回归输入契约、搜索排序/范围/容量、UUID/无ID状态、非语音Run、私有历史隔离、文件路径/大小、正文截断及PDF、取消、异步宿主隔离、UI结果解析。真实模型/语音/用户成果不参与隔离测试。执行contracts/core/API相关测试、renderer构建、并发回归、文档构建。无数据迁移，无新索引；关闭工具入口可回滚，保留所有历史记录与文件。

首期不索引任意磁盘文件、不提供全库正文语义检索或模板任务管理页独立json-result搜索；已归档成果可搜索，普通对话关联运行可读取。项目成果按资产登记可发现，不把未完成分片或未归档项目草稿当已交付成果。首期无自动修改/重新生成、自动创建Skill或经验。

WR-R6 / WR-T6（漏检修复）：文件名检索支持自然语言常用前缀、到/至、五天/5天和分词组合，不要求整句连续出现；“这个PDF”在当前对话按文件类型查找。每次只读取最多500条当前所有者的资产元数据，候选超限明确提示，不扫描文件正文。当前范围兼容通过本会话最近100个有效Run关联、缺少conversationId的旧资产；不得关联其他会话或其他用户的资产。文字Run按标题或本Run关联消息匹配，不仅按会话标题匹配。空结果明确实际范围，模型不得将current空结果说成历史不存在，历史查询需另行调用history。覆盖文件名变体、多关键词、无关文件排除、旧资产关联、跨用户/会话隔离、普通消息正文检索；不改变输入契约，无迁移。

WR-R7 / WR-T7（LLM语义筛选）：非空query默认对有权限的候选执行一次LLM语义筛选，关键词只负责召回优先级与失败兜底，不作为语义候选的强制过滤条件。候选包含真实kind/id、名称、时间和关联会话的有界需求/回答摘要；最多60项，不读取文件正文，不新增向量库。模型仅在agent-core调用，普通执行使用当前Run的模型，语音使用当前员工的文字模型，禁用联网搜索；单次最长12秒、无自动重试、响应最多1200 tokens。仅保留候选内、去重、置信度≥0.65的ID，模型不得改写文件信息。模型缺失/超时/非法响应明确返回partial与fallback，保留关键词候选，不能说成语义确认无成果。有效空结果只代表本次有界候选未匹配；current空结果仍需再查history。模型前后复核来源权限；取消不返回筛选结果。

契约版本1.1：WorkResultItem增加可选summary（最多600字符）；WorkLookupResult增加可选searchMode（keyword/semantic/fallback）与scope，新客户端可解析旧结果，无存储迁移。旧客户端使用严格Schema，不能混用新API：需同时加载新版API/renderer并重新开始通话。WR-T7覆盖无共同关键词的语义命中、ID伪造/类型混淆/重复/低置信度、非法响应/模型失败/超时/取消兜底、关键词保留、当前/历史范围、共享/撤权隔离、语音和普通Run接入、真实SDK本地桩调用；无真实用户成果或付费调用。回滚API/renderer同版代码即可恢复关键词模式，历史文件与数据不变。

WR-R8 / WR-T8：内置PDF读取共用本地中文CMap资源，不访问CDN；解析异常与真实空文字分开提示，空文字不直接认定扫描件。语音读取已授权PDF失败时，自动复制原始PDF为附件，转交当前私有对话员工进行逐页提取；员工通过既有Skill授权/审批执行，不自动安装或授权Skill，不重写原PDF，不再次委托自己。原始附件即使内置解析失败仍能交付至持续任务的.task/source/。同一通话同一资产最多提交一次，已有活动Run不得中断；无权限/失效账号/文件不安全不触发转交。返回accepted仅表示接手，包含真实taskId/conversationId，复用既有任务状态、取消及完成通知；完整处理结果保存在关联对话，语音可继续按Run ID读取，不把历史摘要当PDF原文。普通Agent读取失败得到明确Skill处理建议，本轮不为普通工具自动创建递归任务。
