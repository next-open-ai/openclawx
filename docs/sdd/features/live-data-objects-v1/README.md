# 实时数据库对象 v1

规格版本：1.1；更新：2026-10-12；状态与证据见 [status](status.md)。

## 需求与边界

- LDO-R1：独立保存、复用 MySQL / PostgreSQL 连接；密码仅存桌面 safeStorage。桌面开发模式的独立 API 经 LDO-R8 桥读取；无桌面的纯 API 模式只存会话内存，重启需重新输入。
- LDO-R2：选择连接、数据库、1–20 张表创建实时对象；只登记元数据，不复制业务行。已有快照原样保留，标注“本地副本”。
- LDO-R3：沿用对象、表、列说明编辑；显示名和说明不能改变真实表/字段绑定。
- LDO-R4：Gateway 实时参数化查询，owner + org 隔离，最多返回 200 行；不接受任意 SQL。
- LDO-R5：实时对象缺省只读；仅对象所有者且为管理员显式确认后启用写入。无主键表、含二进制字段的表及 MySQL 非 InnoDB 表始终只读；支持复合主键。修改/删除使用 15 分钟签名记录标识与原值比较，冲突须刷新，不自动重试。
- LDO-R6：对象内提供查询、新增、修改、删除测试界面；真实写入明确确认，失败显示可操作原因。删除对象不删除原库数据。
- LDO-R7：读取与写入错误不暴露凭据；连接断开后的写入结果不确定时明确要求核对原库，禁止自动重试。

## 契约与兼容性

### LDO-R8 / T5 · 桌面开发态安全凭据持久化（2026-10-12）

连接元数据已落盘；开发 supervisor 独立启动 API，没有 Electron fork IPC，原会话密码因此在 API 重启后丢失。新增主进程 loopback 随机端口凭据桥，运行期随机 capability token，仅内部桌面身份可向 API 注册 port/token（Zod 契约）。API 按需读写 Electron safeStorage，与已有 IPC 使用同一密文键；描述符/解密密码只存内存，不进入 domain、连接元数据、日志或 renderer。桥不可用时明确报错，不静默降级内存或明文。已有纯内存密码在桥接后下一次访问迁移到安全存储；已丢失密码需补填一次。无桌面的纯 Node 服务仍是会话模式。

测试 T5：合成安全存储跨 API 模块重建恢复，空密码、写失败不成功、错误 token/Origin/参数/超大请求拒绝、未授权桥注册拒绝、共享 IPC/HTTP 密文键、内部描述符不泄漏；不访问用户业务库或真实钥匙串。回滚桥注册和客户端即可保留已有密文，禁止删除凭据。

contracts/data-schema：连接创建、实时对象创建、写入策略、记录请求；API `/data/connections`、`/data/sources/live`、`/data/sources/:id/access`、`/data/gateway/records`。
新增两张元数据表，旧表和快照不迁移、不刷新、不写回。实时对象不得落入旧本地副本读写/应用发布路径。
本需求对 remote-database-v1 的“连接不可复用、只导入快照”限制仅针对新实时对象扩展。
回滚：停止新实时对象功能并保留元数据；旧快照照常使用；不得删除或修改原数据库。

## 任务与验证

- LDO-R9 / T6：创建应用遇到缺失密码时，打开绑定连接的专用修复窗口，只填写密码并测试保存，不显示新建连接/选表/建对象。保存后服务端再次读取确认，成功返回原应用草稿并显示可重试；失败保留窗口、显示原因，不自动启动模型。已有遗失密码不可恢复，不据此宣称持久化再次失败。测试覆盖正确连接 ID、权限隔离、保存回读、失败不返回、原应用需求保留；无存储结构迁移，回滚 UI 不删除密文。

- LDO-T1 → R1/R2：连接凭据与元数据隔离、表发现、对象登记；合成连接集成测试。
- LDO-T2 → R3/R4/R5/R7：受控 SQL、权限、主键、冲突、失效记录、错误脱敏回归。
- LDO-T3 → R2/R6：工作台入口、模式标注、只读/写入确认、CRUD 状态；renderer 类型检查与构建。
- LDO-T4：真实 MySQL/PostgreSQL 验收需隔离实例和凭据，本轮不得测试用户业务库。智能体专用工具及 AI 应用实时绑定另行接入，不伪称完成。
