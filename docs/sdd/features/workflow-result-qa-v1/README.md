# 工作流成果问答 · WQ-V1

状态：已实现，隔离回归通过；真实供应商验收待单独安排。规格 1.0；2026-10-10。关联 [WC-V1](../workflow-chat-v1/README.md)、[WP-V1](../workflow-project-v1/README.md)。

## 范围、需求与任务

- WQ-R1/T1：先接入普通对话卡片“基于成果提问”。点击只选择依据，不调用模型；输入区明确显示工作流名、运行状态、取消入口及“仅问答，不修改文件”。发送后保留选择便于连续提问，切换/清空对话清除。运行中/审批中不可提问；失败或取消允许基于标注的部分输出提问；无真实文本时明确拒绝。项目续聊仍是增量修改，本期不将问答混入项目 DAG。
- WQ-R2/T2：GET `/sessions/:sessionId/workflow-invocations/:requestId/evidence` 仅返回本人该来源调用的有界真实输出、状态及文件引用。POST 原 messages 接口新增可选严格 `workflowResult:{invocationId,revision}`。服务端重新校验来源、调用人、执行项目读权限与证据指纹，不接受客户端自报文本/路径；状态变化或重跑后 409，要求重新选择。被撤权/删除/跨组织一律不可取数。
- WQ-R3/T3：只使用最新实际 Run 的有界文本与登记清单，不扫描或读取文件正文、不赋予工作区权限、不称已读 PDF。注明截断、失败/取消及证据时间；模型需按材料作答，缺失则说明。问答走当前对话模型的单轮纯文本流，关闭工具、网络搜索、Skill/MCP/记忆工具及文件交付校验，不调度工作流、不创建持续任务。即使用户说“重跑/修改”，也只解释需进入执行项目。保留 Run/usage/取消/失败链路。
- WQ-R4/T4：复用来源对话消息及流式 Run UI，失败保留草稿/依据，源切换不串上下文。成果问答时禁止协作/自动调度、图片/文档/录音混入；服务端拒绝附件混入，活跃来源拒绝覆盖正在执行的工作。
- WQ-R5/T5：契约/权限/撤权/旧指纹/部分结果/无证据/工具隔离/持续任务隔离及浏览器选择取消切换、失败保留、移动端验证。临时存储和确定性 runner；默认不调用真实付费模型。真实模型链路本期未承诺已验收，须用户明确选择连接与材料后另行实测。

## 契约与边界

WorkflowResultReference 是调用 id + SHA256 revision；WorkflowResultEvidence 是服务器投影（24k 文本，最多 30 个最新任务，每任务 8k，50 个登记文件；限制处明确截断）。revision 覆盖投影内容、项目 activeRunId、task runId，不持久化第二份运行状态。API 是证据关联验证者，Run/Project 是真相源。

ChatRequest 增加可选 responseMode=text-only；纯文本执行经 agent-core 的 Pi 模型协议适配器直接流式调用，不加载任何执行后端工具/工作区，执行事件标记 pi。问答保留当前模型，但不继承员工工具引擎；原普通对话行为缺省不变。服务端生成的依据使用已存在 attachmentContext 隐藏字段保存，消息额外保存公开引用与 responseMode。单轮问答只使用当前问题和本次证据，历史回答不冒充新证据；再次发送均重新验权。

引用区明确提示答案按当前对话共享范围可见。已选依据作为该消息历史快照保存；撤销执行项目权限只拦截后续取数/发送，不追溯删除已有对话历史。
