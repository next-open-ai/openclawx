# Project application snapshots v1

Specification version: 1.0 · Updated: 2026-10-10 · Related: [LP-V1](../lightweight-project-v1/README.md), [project architecture](../../../architecture/project-orchestration.md).

## Requirements / tasks

- PA-R1 / PA-T1: validate existing lightweight project create → independent turns → modification/failure retention with LP regressions. No new DAG or execution engine.
- PA-R2 / PA-T2: conversation-kind projects only; authorized read detects root `index.html` or `output/index.html`, previews an immutable static bundle. Reject symlinks/traversal/special files and enforce bounds. Exclude inputs, tool scripts, metadata, dependencies and non-web files. No credentials or whole project archive published.
- PA-R3 / PA-T3: explicit write-authorized publication requires the preview content revision and previous published version. Publish only while idle; prepare immutable disk snapshot first, then atomically persist the publication pointer. Concurrent/stale requests return conflict. Failure preserves previous pointer and content. Same-content retry is idempotent. New turns/editor changes never auto-publish.
- PA-R4 / PA-T4: project header application entry opens a native dialog, with missing-entry/error/loading states, sandboxed preview, confirm publish/update and open published version. Disclosure: local static hosting, no public cloud deployment, no arbitrary backend/API access. Existing data-app publication unchanged.
- PA-R5 / PA-T5: serving uses bounded, in-memory expiring read-only view tickets, never full session tokens. Each request rechecks project read permission against the issuing principal. Ticket pins one snapshot, expires after 30 minutes or API restart. CSP sandbox prevents generated HTML from gaining OpenClawX origin/storage/auth privileges; external subresources and fetch/WebSocket connections disabled. This is not comprehensive browser-navigation/network containment; preview trusted outputs only. Links are temporary viewing links, not permanent public sharing.

## Contracts

Secured `/api/orch/projects/:projectId/application`: GET metadata; POST `/preview` prepares snapshot and view ticket; POST `/publish` strict `{revision, expectedVersion: string|null}` validates preview revision against current bundle and publication pointer; POST `/view` issues ticket for published snapshot.

Read-only `/api/project-sites/:ticket/*`: serves only the pinned snapshot's allowlisted resources. No arbitrary filesystem root or relative path from the client enters creation/publication. Metadata uses versioned `project-application:v1:<projectId>` in API-owned KV; snapshots live outside project workspace under data directory. No stored-project migration; rollback hides entry, immutable files/metadata remain recoverable.

Limits / rollout: immutable static snapshots only, relative resource URLs, no backend process, allowed external subresources/fetch connections, OpenClawX storage/API access, cloud deployment or permanent anonymous sharing. Ordinary browser navigation is not comprehensively contained; preview trusted outputs only. View tickets pin one snapshot and expire after 30 minutes/API restart, with project-grant recheck; they are read capabilities and must not be forwarded to unauthorized recipients. Old immutable snapshots are retained (no automatic garbage collection/rollback UI in v1). Limits are not an OS sandbox or fully journaled power-loss transaction; do not place credentials in HTML/JSON resources. Existing project paths, legacy DAG/workflows and data-app binding are unchanged. Restart development API and refresh renderer; no migration, no user projects published/restarted during acceptance.
