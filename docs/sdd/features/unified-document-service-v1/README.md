# UD-v1 · 统一文档读取与通用委托

2026-10-14；已实现并完成隔离回归，真实模型/第三方Skill待验收。继承工作成果检索WR-R1–R8的权限、路径、资源及有界处理规则；本规格取代WR-R8的“语音桥接自动判断PDF失败并派单”行为。证据见[验证记录](status.md)。

UD-R1/T1：agent-core提供readDocument(input)统一入口，接收已授权宿主提供的文件名/字节及容量、页数、字符、取消、增强解析选项，不接受模型路径或URL。统一结果契约在contracts：成功/失败、格式、解析器、正文、页数/截断、警告、稳定错误码与建议动作。覆盖已有PDF、DOCX、PPTX/PPSX、文本/Markdown/代码、HTML、CSV/XLS/XLSX；DOC等未支持格式明确失败。基础内置读取不调用LLM、Skill、网络服务或创建任务；可选增强组件仅由调用方显式允许且已配置可用时执行，沿用组件现有配置，不自动安装。

服务是应用内模块，不新增独立进程/端口。新入口调用readDocument并复用DocumentReadResult契约；文件访问/所有权仍由宿主负责。Pi/AgentScope的read_document工具将工作区相对路径解析成受限文件字节后再调用服务；DSH本轮未新增对应宿主工具，既有Skill执行不变。

UD-R2/T2：资产正文读取、聊天附件、LanceDB文档导入共用统一服务，删除重复格式解析分支。API宿主继续负责登录、文件所有权、路径安全、前后撤权检查，不因服务复用扩大权限。资产默认10MB/20页/16000字符；附件沿用既有格式限额。本地知识库文件入口统一25MB/300页/50万字符，截断则拒绝索引并提示拆分，不冒充完整入库；直接文本导入与现有嵌入模型配置门槛不变。读取失败只返回错误与delegate建议，绝不自己派单；空文字不认定扫描件。Pi/AgentScope新增read_document工具，仅允许受限工作区相对路径，默认20页/6000字符，最大25MB/300页/16000字符。

UD-R3/T3：语音桥接仅身份绑定、函数转发、幂等调用缓存和状态回传，无PDF分支/文件拷贝/解析器选择。start_work扩展可选assetIds（最多5个真实归档资产ID），由模型明确调用才委托当前/指定员工；通用委托服务负责逐项权限复核、原文件副本附件化、Skill授权/审批和任务派发。既有无附件调用兼容；忙碌不打断，失败不伪造accepted。文档内容是资料不是指令；不自动安装Skill，不修改原资产。普通Agent可直接使用同一读取能力及既有Skill，不自动递归派单。

UD-R4/T4：读取工具向语音/普通模型解释“先基础读取，复杂或失败时使用已授权Skill/通用委托”；保留已读正文与来源，不把摘要当原文。原始文档即使无法解析，也可通过显式委托交付至.task/source/。任务状态、取消、完成通知复用既有协议，只有start_work accepted进入自动通知。

契约1.3：新增DocumentReadResultSchema；WorkLookupResult可选documentInfo（不重复正文），VoiceWorkStartSchema可选assetIds。不迁移历史文件/数据库；严格Schema客户端与API需同步更新，重新开始通话。parseLocalDocument保留作为兼容的底层二进制引擎，新增调用优先使用readDocument。不新增HTTP微服务，不更换Provider或Skill授权机制，不实现文档编辑/格式转换的新能力。

验证：UD-T1跨格式、中文CID、空内容、坏文件、容量/页数/字符截断及取消；UD-T2三个入口真实调用/本地隔离回归；UD-T3桥接读取失败不派单、显式携带附件委托成功/完成/取消/忙碌/无模型/越权、原件不变；UD-T4工具契约、UI错误/任务状态、既有语音协议回归。执行contracts/core/API测试与类型检查、renderer构建、并发/文档/资源回归；不调用付费模型或真实用户文件。回滚本轮模块/契约和入口改动可恢复前一版，不删除成果。
