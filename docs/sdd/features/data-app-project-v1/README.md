# 数据应用专属项目 · 第一期

范围仅 OpenClawX 数据应用入口；不改普通对话、不自动迁移旧应用、不实现 Schema 版本或多员工规划。替代 DAC-R4/R7 的新建模板/普通对话入口，旧 API 与历史模板兼容保留。

## 需求 / 任务 / 契约

- DAP-R1/T1：创建只展示数据表、名称与需求，不提供应用类型选择，不在制作/优化 Prompt 注入类型偏好；AI 按用户描述和 Schema 决定交互形态。新建记录统一为“自定义应用”，不限制业务场景；旧请求的 appType 可选兼容但不作为生成约束。自动建立应用专属私有项目，采用一个任务串行完成理解、制作、验证与绑定。服务端项目调度使用现有 RunEngine，前端只跳转项目对话，不执行模型。
- DAP-R2/T2：新增 project-create / project-execute API；请求含 UUID requestId、employeeId 与权限档位。创建按用户/requestId 幂等，重复键不同内容返回 409；应用与项目的稳定关联先持久化，跨 SQL/KV 无分布式事务，以确定性项目 ID 和 createDraftOnce 恢复半完成准备。自动启动至多一次；不确定启动结果不盲目重复，用户在原项目继续。
- DAP-R3/T3：后续创建/优化复用原应用、项目、员工、权限与固定工作区。执行请求以 requestId 幂等；读取最新 Schema。已有运行拒绝并发优化；已发布页面失败仍可用。旧应用仅在用户明确优化时关联项目；已删除项目不静默建立替代项目。
- DAP-R4/T4：新增可选 projectId，不修改旧数据事实。项目目录由服务器生成，不接受客户端路径；数据项目选择隔离 Run 工作区，正常交付晋升固定项目目录。普通项目默认行为不变。上下文解析传递项目所有者，读取其 Skill/模型偏好；不持久化模型密钥。
- DAP-R5/T5：项目链接、继续创建、优化进入项目。提交失败保留输入和幂等键；编辑后生成新键。准备成功但启动失败明确提示并提供原项目入口，不让用户重复创建。完成与应用可用分离，以实际绑定为准。

契约入口：contracts/data-schema 的项目创建/执行请求及执行响应。SQL 新增请求/关联/操作表，幂等建表，无删除或旧数据重写；回滚保留新增表，恢复旧 UI/API 入口即可。

## 验证

DAP-T1/T5：Vue setup 回归验证无模板/类型选择、提交不携带类型、单次提交、重试键稳定、项目跳转与无普通对话事件；API 验证无类型请求可创建，Prompt 无“类型偏好”，新记录为自定义应用。旧模板 API 保留，无历史数据迁移。
DAP-T2/T3：隔离 Fastify + SQL + Orchestrator API 回归验证并发重复创建、冲突键、权限隔离、最新 Schema、稳定链接、操作去重、失败保留旧 HTML、已删除项目错误。合成 runner 不宣称真实模型验收。
DAP-T4：orchestrator 回归验证 createDraftOnce 所属权、并发幂等，隔离执行请求不包含项目写目录，普通项目兼容和 owner 上下文。相关包类型/构建/测试，并运行并发专项回归。

真实模型创建/绑定及桌面端到端另行验收，不绕过登录或读取用户密钥。
