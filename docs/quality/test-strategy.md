# OpenClawX 测试策略

> 状态：当前质量总览  
> 更新日期：2026-10-07

## 1. 测试金字塔

| 层级 | 目的 | 环境 |
| --- | --- | --- |
| 静态检查 | 类型、构建、依赖边界、文档链接 | CI |
| 单元测试 | 纯函数、Schema、状态机、策略 | CI |
| 契约测试 | API、事件、Provider、Tool/MCP、配置迁移 | CI + mock |
| 集成测试 | API、KV、SSE、Sidecar、临时工作区 | CI/本地 |
| 专项回归 | 并发、dsh、MCP、通道、打包 | CI/受控环境 |
| E2E | 桌面/UI、真实模型、真实通道 | 受控环境 |
| 发布验收 | 安装包、迁移、灰度、回滚 | 候选发布环境 |

## 2. 准入原则

- 公共行为必须有自动回归；
- 外部模型和第三方系统默认使用 mock/stub，真实服务作为受控 E2E；
- 平台特征 Benchmark 独立在 `docs/benchmarks/` 管理；被发布标准引用时，其阈值结果才进入质量门禁；
- 测试报告必须记录提交、环境、命令、数据集和结果；
- 未执行不等于通过；非确定性结果必须给出重复次数和波动范围。
- 本机测试控制台是白名单回归与证据查看入口，不把预览、异常中断或真实环境未执行项计作通过。

## 3. 证据归档

- 功能测试规格：`docs/sdd/features/<feature>/test-spec.md`；
- 阶段测试报告：`docs/deliverables/<feature>/`；
- 功能阶段测试结果：`docs/quality/features/`；
- 版本回归与验收：`docs/quality/releases/`；
- 平台特征评测：`docs/benchmarks/`；
- 发布验收：`docs/releases/`；
- 原始大体积日志和数据集不直接塞入 Git，文档记录内容哈希和受控位置。
