QUICK GUIDE

从回归到发布基线

让测试有顺序，也让结论有边界。

01

日常改动：先跑快速回归

快速回归执行 API 测试与 Renderer 类型检查；语音或编排改动请选择对应专项套件。

全部套件成功才判为通过，源码测试不能替代桌面端人工交互验收。

02

并发验证：先预览再执行

预览不会向 OpenClawX 服务发送请求，也不计入通过率；实测前确认本地 API 已启动。

持续任务和运行时测试可能创建临时会话，执行记录与日志会保留在本机。

03

发布前：运行完整基线

完整回归依次运行全仓测试与生产构建，耗时更长，适合作为发布候选验收。

构建通过不代表外部模型、网络服务与真实设备一定可用，仍需针对目标环境验收。

04

安全与结果

控制台只监听 127.0.0.1，仅运行预置白名单命令，不接受用户输入的 Shell 命令。

执行数据保存在 tests/console/data；一次只运行一个测试，避免测试互相干扰。
